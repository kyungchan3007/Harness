# 0040 — 시료 보관 엔진 확장 — Trace

에이전트가 **작업하는 동안** 직접 남기는 과정 기록입니다. 도구 호출 전체는 hooks가 `trace.auto.jsonl`에 자동으로 남깁니다(`pnpm trace 0040`으로 확인).
직접 기록에는 자동 기록이 못 남기는 것, 즉 **판단과 이유, 막힘, 되돌림**을 씁니다.

| 순서 | 단계 | 한 일 | 판단·이유 |
| --- | --- | --- | --- |
| 1 | CLAIM | `task/0040-lab` 확인, TASKS에 0040 in-progress 추가 | 이슈 #1 브랜치가 이미 체크아웃된 상태 |
| 2 | 원문 고정 | `pnpm request 1` 시도 → 실패(git remote 없음, gh 조회 불가). `request.md`에 작업 요청 원문을 옮겨 씀 | 원문 불변 규칙은 유지, 복사 경로만 수동. 실패 사실을 request.md에 명시 |
| 3 | DEFINE·PLAN | prd.md(가정 목록 포함)·sdd.md 작성 후 구현 착수 | 가정은 prd "애매한 곳" 칸에 `(가정)`으로 기록. 업무 값(금액 등) 없음 → 확인 필요 항목 없음 |
| 4 | BUILD | 상태에 `claimed`(운송 목적 확보) 추가, `isFree`가 점유+확보를 봄, 격리·등급·만료·운송 명령 구현 | 판정은 docs/*.md 문면을 우선. 운송 목적 확보를 `occupied`에 넣으면 E1 "시료 하나 = 용기 하나"가 깨져서 별도 맵 |
| 5 | 막힘 | 테스트 2건 실패: (a) `setup("FROZEN")`이 CHILLED용 C1에 받으려 함 (b) 재확인 `confirmArrival`을 새 eventId로 보냄 | 둘 다 테스트 쪽 실수. (a)는 등급별 용기 선택, (b)는 같은 eventId 재전송은 Receipt, 새 eventId는 TRANSIT_CLOSED로 수정. 구현 규칙은 바꾸지 않음 |
| 6 | 막힘 | 분취 자식을 C3에 넣으려 했으나 C3는 시료가 점유 중 → CONTAINER_OCCUPIED | 테스트 카탈로그에 FROZEN 용기 C5 추가 |
| 7 | RECORD | 태스크 기록 검사: "(가정)" 표시 누락 3줄, "(확인 필요)" 키워드 포함 줄, "없음" 줄 혼합 금지 | 체커 규칙에 맞춰 prd 가정 칸 정리. 실제 질문 필요 항목은 없음 |
