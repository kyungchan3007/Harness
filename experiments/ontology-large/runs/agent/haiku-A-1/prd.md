# 0040 — 시료 보관 엔진 확장: 격리·보관 등급·예약 만료·운송 — PRD

- **이슈:** #1
- **문제:** 시료 보관 엔진(`src/lab/`)은 받기·분취·예약·소비·폐기·이동·책임자 변경까지만 된다. 품질 격리, 보관 등급 적합성, 예약 만료, 용기 간 운송이 빠져 있어 실제 연구실 흐름을 표현하지 못한다.
- **목표:**
  - 기존 명령의 동작을 바꾸지 않고 격리·보관 등급·예약 만료·운송을 `createLab` 공개 계약으로 추가한다.
  - 실패는 예외가 아니라 `{ ok: false, code }`로 돌려준다.
- **비목표:**
  - 실제 시계, 외부 저장소, 동시 호출 처리.
  - `src/lab/types.ts` 수정.
  - 저장소에 적히지 않은 실제 연구실 관행 추가.

## 애매한 곳·가정
- 요청 원문은 `docs/`의 정책 문서 다섯 개와 `types.ts`, 구현 주석을 기준으로 삼는다 — 요청 자체가 지정한 기준이라 충돌 없음 (확인됨: 요청 원문 "기존 문서와 코드 계약을 따르세요")
- 분취 자식의 보관 등급은 부모 등급을 상속 — `samples.ts` 정책 주석과 `storage.md`가 일치 (확인됨: 저장소 정책)
- 여러 규칙을 동시에 어기는 경우의 오류 코드는 E6대로 자유 — 검사 순서는 입력 → 재전송 → 시료·예약·운송 상태 → 격리·운송 중 → 보관 등급 → 용기 점유 → 용량 → 양 (가정)
- 격리 중 예약 소비는 예약이 아직 ACTIVE인지를 먼저 보고 격리를 본다, 즉 `RESERVATION_CLOSED`가 우선 (가정)
- 운송 ID 재사용은 끝난 운송 포함 `ID_TAKEN` — `transit.md` 기록·식별자 규칙 (확인됨: 저장소 정책)
- 시각 진행 `to === now`도 성공하며 이벤트를 남긴다 — E6 "성공한 새 명령마다 이벤트" (가정)
- 원문 파일(`request.md`)은 `pnpm request`가 GitHub 이슈를 읽어 만든다. 이번 실행은 웹 접근 금지라 생성하지 않았고, 원문은 작업 지시문 그대로를 판정 기준으로 본다 (가정: 이번 세션은 웹 접근 금지라 `pnpm request` 생성 생략, 이 작업 지시문이 판정 원문. 나중에 이슈 본문과 대조 필요)

## Acceptance
- [x] `quarantine`·`release`: ACTIVE 시료 격리 설정, 같은 상태에서도 성공, 격리된 시료의 분취·새 예약·예약 소비는 `QUARANTINED`
- [x] 격리는 예약 취소·이동·폐기·책임자 변경·운송을 막지 않는다
- [x] 받기·분취 자식·이동·운송 시작의 목적 용기가 요구 등급을 지원하지 않으면 `STORAGE_INCOMPATIBLE`, 등급은 지원 목록에 정확히 있어야 한다
- [x] `advanceTime`: 현재 이상의 유효 절대 시각만 받고, 과거·잘못된 값은 `INVALID_INPUT`
- [x] 새 예약의 `expiresAt`은 `null` 또는 현재보다 미래인 유효 시각, 아니면 `INVALID_INPUT`
- [x] 시각 진행으로 만료된 ACTIVE 예약은 `EXPIRED`가 되고 예약 양만 풀린다, 남은 양·소비량·폐기량은 그대로
- [x] `startTransit`·`confirmArrival`·`cancelTransit`: 운송 ID 고유, 도착은 시료를 옮기고 `ARRIVED`, 취소는 `CANCELED`와 목적 확보 해제
