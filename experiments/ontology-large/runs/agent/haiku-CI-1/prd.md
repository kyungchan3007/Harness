# 0040 — 시료 보관 엔진 확장: 격리·보관 등급·예약 만료·운송 — PRD

- **이슈:** #1
- **문제:** 시료 보관 엔진(`src/lab/`)에 격리, 보관 등급, 예약 만료, 운송 기능이 빠져 있어 `createLab`의 공개 계약 일부가 미구현(throw)이거나 임시값(분취 등급 "AMBIENT" 고정)으로 남아 있다.
- **목표:**
  - 격리·해제(`quarantine`·`release`)를 구현하고, 격리된 시료의 분취·새 예약·예약 소비를 `QUARANTINED`로 거절한다.
  - 받기·분취·이동·운송 시작의 목적 용기가 시료의 요구 보관 등급을 지원하지 않으면 `STORAGE_INCOMPATIBLE`로 거절한다. 분취 자식은 부모 등급을 상속한다.
  - 논리 시각 `advanceTime`을 구현하고, 만료 시각이 된 ACTIVE 예약을 `EXPIRED`로 바꿔 예약 양만 푼다.
  - 운송(`startTransit`·`confirmArrival`·`cancelTransit`)을 구현하고, 운송 중에는 분취·소비·폐기·직접 이동·추가 운송을 `IN_TRANSIT`으로 거절한다.
  - 기존 기능(재전송·원자성·이력 규칙)은 그대로 유지한다.
- **비목표:**
  - `src/lab/types.ts`와 `docs/`의 정책 문서는 고치지 않는다.
  - 실제 시계, 외부 저장소, 동시 호출은 다루지 않는다.
  - 저장소에 적히지 않은 실제 연구실 관행은 더하지 않는다.

## 애매한 곳·가정
- 분취 자식의 격리 상태는 `false`로 시작한다 (가정). 문서에 정함이 없고, 격리는 시료 생애와 따로 보는 값이라 부모에서 잇지 않는다.
- 같은 명령이 여러 규칙을 어기면 어느 오류 코드를 돌려줘도 된다 (docs/engine.md E6.4). 구현은 "재전송 판정 → 존재 → 상태 → 격리 → 운송 → 용기·용량 → 등급" 순서로 검사한다 (가정).
- 보관 등급 값이 세 가지 밖이면 `INVALID_INPUT`으로 본다 (가정). ontology.json의 `receive` 조건 "등급 값(INVALID_INPUT)"을 따른 것이다.
- `advanceTime`에 현재와 같은 시각을 주면 성공하고 이벤트를 하나 남긴다 (요청 "현재 이상"을 따름, 가정 없음).
- 새 예약의 만료 시각이 현재와 같으면 `INVALID_INPUT`이다 (요청 "현재보다 미래"를 따름, 가정 없음).
- 운송 시작 전에 시료가 격리되어 있어도 운송을 막지 않는다 (docs/quality.md·docs/transit.md를 따름, 가정 없음).
