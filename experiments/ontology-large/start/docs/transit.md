# 운송 절차

운송은 시료를 다른 용기로 옮기는 2단계 절차입니다: `startTransit` → `confirmArrival`(도착) 또는 `cancelTransit`(취소).

## 상태와 점유
- 운송 상태는 `ACTIVE` → `ARRIVED` 또는 `CANCELED`.
- **운송이 시작되면 끝날 때까지 시료는 출발 용기를 계속 점유하고, 목적 용기는 그 운송이 배타적으로 확보합니다.** 확보된 목적 용기는 다른 시료의 받기·분취·이동, 다른 운송의 목적지로 쓸 수 없습니다(`CONTAINER_OCCUPIED`). 판정은 용기 구현의 규칙을 따릅니다(`src/lab/storage.ts`).
- 도착 확정은 시료를 목적 용기로 옮기고(출발 용기는 빔) 운송을 `ARRIVED`로, 취소는 시료를 출발 용기에 둔 채 운송을 `CANCELED`로 하고 목적 확보를 풉니다. 도착·취소는 시료의 양·계보·책임자·보관 등급·격리 여부를 바꾸지 않습니다.

## 운송 중 명령
- 금지(`IN_TRANSIT`): 분취, 소비, 폐기, 직접 이동(`move`), 같은 시료의 추가 운송 시작.
- 허용: 새 예약, 예약 취소, 책임자 변경, 격리·해제, 시각 진행. 각 명령의 다른 제한은 그대로입니다.
- 운송 중 금지된 명령이 실패하면 실패 규칙([engine.md](engine.md) E6)대로 시료·예약·양쪽 용기·운송·이력이 그대로이고 그 eventId도 소모되지 않습니다.

## 기록·식별자
- **끝난 운송은 기록과 식별자를 남깁니다.** 운송 ID를 다시 쓰면 `ID_TAKEN`, 없는 운송을 조작하면 `UNKNOWN_TRANSIT`, 끝난 운송에 새 이벤트로 도착·취소하면 `TRANSIT_CLOSED`.
- 도착·취소가 끝난 뒤 같은 성공 이벤트를 다시 보내면 [engine.md](engine.md) E5대로 처음 Receipt를 돌려주며, `TRANSIT_CLOSED`를 내거나 이동·이력을 더하지 않습니다.
