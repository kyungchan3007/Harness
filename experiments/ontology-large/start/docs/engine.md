# 엔진 공통 계약

시료 보관 엔진의 모든 명령에 적용되는 규칙입니다. 새 명령(격리·시각 진행·운송)에도 그대로 적용됩니다.

## 대상
- 장소·용기·보관 책임자는 `createLab`에 넘긴 목록에 있는 것만 존재합니다. 용기는 장소 하나에 고정돼 있고 용량과 지원 보관 등급이 있습니다.
- 시료는 용기에 담긴 액체이고, 양은 정수 μL입니다. 예약은 시료의 일정량을 쓰겠다고 잡아 둔 것입니다. 이벤트는 성공한 명령 하나의 기록이며, 모든 명령은 첫 인자로 `eventId`를 받습니다.

## E1 참조·수용
1. 없는 용기는 `UNKNOWN_CONTAINER`, 없는 책임자는 `UNKNOWN_CUSTODIAN`, 없는 시료는 `UNKNOWN_SAMPLE`, 없는 예약은 `UNKNOWN_RESERVATION`.
2. ACTIVE 시료는 반드시 용기 하나에 담겨 있고, 용기 하나에는 시료가 최대 하나입니다. 차 있는 용기에 넣으려 하면 `CONTAINER_OCCUPIED`.
3. 시료의 남은 양은 담긴 용기의 용량 이하입니다. 넘으면 `CAPACITY_EXCEEDED`.
4. 시료 ID·예약 ID는 한 번 쓰면(끝난 뒤에도) 다시 쓸 수 없습니다 → `ID_TAKEN`. ID는 종류마다 따로 고유합니다.
5. 양은 1 이상 1,000,000 이하의 정수입니다. 아니면 `INVALID_INPUT`. 분취할 자식 목록이 비어 있어도 `INVALID_INPUT`.

## E2 계보·수량 보존
1. `receive`만 계보의 시작 시료를 만듭니다(parentId null, rootId 자기 자신).
2. `split`은 부모에서 새 자식을 한 번에 1개 이상 만들고, 자식 양의 합을 부모의 남은 양에서 뺍니다. 자식의 parentId는 부모, rootId는 부모의 rootId. 계보는 나중에 바뀌지 않습니다.
3. 나눠 담을 수 있는 총량은 부모의 이용 가능량 이하입니다. 넘으면 `INSUFFICIENT`.
4. 분취는 소비가 아닙니다. 계보마다: 시작 시료가 받은 양 = 계보 안 모든 시료의 남은 양 + 누적 소비량 + 누적 폐기량.

## E3 상태·폐기
1. 시료 상태는 `ACTIVE`·`DEPLETED`·`DISCARDED`. 분취나 소비로 남은 양이 0이 되면 `DEPLETED`.
2. `discard`는 ACTIVE 예약이 없는 ACTIVE 시료의 남은 양 전부를 버립니다(discardedQty, 남은 양 0, `DISCARDED`). ACTIVE 예약이 있으면 `HAS_RESERVATION`.
3. 끝난 상태는 되살릴 수 없고, 끝난 시료에 대한 변경은 `NOT_ACTIVE`. 끝난 시료는 용기를 비웁니다(containerId null).
4. 부모가 끝나도 자식에게는 영향이 없습니다.

## E4 용기·장소·책임
1. 시료의 장소는 지금 담긴 용기의 장소입니다.
2. `move`는 다른 빈 용기로 옮깁니다(용량이 남은 양 이상). 지금 용기로 옮기면 `CONTAINER_OCCUPIED`. 이동은 양·예약·계보·책임자를 바꾸지 않습니다.
3. 분취할 자식의 용기도 명령 시작 시점에 비어 있어야 하고, 자식끼리 같은 용기를 쓸 수 없습니다.
4. 분취한 자식은 그 순간 부모의 책임자를 이어받습니다. `transferCustody`는 그 시료 하나만 바꿉니다.

## E5 같은 명령 다시 보내기
1. 이미 성공한 eventId로 같은 명령·같은 인자를 보내면 처음 Receipt를 그대로 돌려주고 상태·이력은 바꾸지 않습니다. 지금 상태로는 실패할 명령이어도 마찬가지이며, 이 판단을 다른 검사보다 먼저 합니다.
2. 같은 eventId로 다른 명령이나 다른 인자를 보내면 `EVENT_CONFLICT`. 객체 키 순서는 무시하고 배열 순서는 구별합니다.
3. 실패한 명령의 eventId는 기록되지 않습니다.

## E6 원자성·이력
1. 성공한 새 명령마다 이벤트 하나를 남기고 seq를 1 늘립니다(첫 seq는 1).
2. 실패하면 양·상태·예약·용기 배정·운송·계보·이력·eventId 기록 무엇도 바뀌지 않습니다. 여러 자식 분취도 모두 성공하거나 모두 실패합니다.
3. 이력은 op와 args(eventId 제외, 모양은 `types.ts`의 `EventView.args`)를 담고, 나중 명령이나 호출한 쪽의 객체 수정이 바꾸지 않습니다.
4. 규칙을 여러 개 어기는 호출은 어긴 규칙의 오류 코드 중 무엇을 돌려줘도 됩니다.
