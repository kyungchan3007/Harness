# 0030 — 포인트 적립 — PRD

- **이슈:** #1
- **역할 분리:** on
- **문제:** 주문을 해도 포인트를 적립하는 규칙이 코드에도 [domain.md](../../../context/domain.md)에도 없다. 원문(이슈 #1)은 "결제 금액의 1% 적립, 쿠폰 쓴 주문은 좀 줄이고, VIP는 더 많이, 1포인트 단위 정수"라고만 하고 **쿠폰·VIP의 구체 수치와 경계 처리를 정하지 않았다**. 수치를 에이전트가 임의로 확정하면 확인되지 않은 비즈니스 결정이 사실처럼 코드에 박힌다.
- **목표:** 주문 금액 계산 결과(`total`, `discount`)와 회원 등급을 받아 적립 포인트(정수)를 돌려주는 순수 함수를 `src/pricing/points.ts`에 만든다. 요율은 코드에 박지 않고 **정책 객체(`PointsPolicy`)**로 분리해 요청자가 값을 바꾸면 코드 수정 없이 반영되게 한다(배송비의 `ShippingPolicy` 패턴). 기본 1%만 원문 확정값이고, 쿠폰·VIP 요율은 아래 "가정/미확정 사항"의 가정값이다.
- **비목표:**
  - 적립 회수(환불·취소 시 포인트 차감) — 이번 범위 밖(별도 태스크)
  - 포인트 사용(결제 시 차감)·유효기간·잔액 저장·영속화·HTTP API
  - 쿠폰 할인 금액 계산(0003). 등급 판정(누가 VIP인가)은 입력으로 받는다
  - `priceCart`·`PriceBreakdown` 변경 (포인트는 별도 함수로 둔다)

## Acceptance
- [ ] 기본 요율 1%: 일반 등급·쿠폰 없음(`discount` 0)에서 `total` 10,000이면 100포인트다
- [ ] 정수화는 내림이고 경계가 정확하다: 일반·쿠폰 없음에서 `total` 99 → 0, 100 → 1, 199 → 1, 200 → 2
- [ ] `total` 0이면 어떤 등급·쿠폰 여부에서도 0포인트다
- [ ] 쿠폰 주문(`discount > 0`)은 같은 등급의 쿠폰 없는 주문보다 적립이 적다: 일반 `total` 10,000·`discount` 1 → 50. 경계 199 → 0, 200 → 1. `discount` 0이면 쿠폰 주문이 아니다(→ 100)
- [ ] VIP는 일반보다 많이 적립한다: VIP·쿠폰 없음 `total` 10,000 → 200. 경계 49 → 0, 50 → 1
- [ ] VIP이면서 쿠폰 주문이면 정책의 (VIP, 쿠폰) 요율을 그대로 쓴다(요율 곱셈 조합 아님): `total` 10,000 → 100. 경계 99 → 0, 100 → 1
- [ ] 기준 금액은 배송비를 포함한 `total`이다: `priceCart`로 만든 `subtotal` 40,000(배송비 3,000, `total` 43,000)의 일반·쿠폰 없음 적립은 430이다. 쿠폰 1,000원(`total` 42,000)이면 210이다
- [ ] 반환값은 항상 0 이상의 정수다 (여러 `total`·등급·쿠폰 조합, `Number.MAX_SAFE_INTEGER`까지 부동소수점 오차 없이 정확: `total` 9007199254740991, 1% → 90071992547409)
- [ ] 입력 검증: `total`·`discount`가 음수·소수·NaN·안전 정수 초과면, 알 수 없는 등급이면 `RangeError`(`assertWon` 재사용)
- [ ] 요율은 정책으로 교체된다: 커스텀 `PointsPolicy`를 주입하면 코드 수정 없이 그 요율로 계산된다 (예: 일반·쿠폰 없음 3% → `total` 10,000에 300)
- [ ] 정책 검증: 요율이 0~10,000(만분율) 정수가 아니거나, 쿠폰 요율이 같은 등급의 일반 요율 이상이거나, VIP 요율이 일반 요율 이하(쿠폰 있음/없음 각각)인 정책은 `RangeError`로 거부한다
- [ ] `DEFAULT_POINTS_POLICY` 값이 domain.md "포인트 규칙 (0030)" 표의 요율과 같다(테스트가 표의 값을 그대로 단언)
- [ ] 기존 `priceCart`·장바구니 테스트가 그대로 통과한다 (`price-cart.ts` 무변경)
- [ ] `pnpm check` ALL PASS

## 가정/미확정 사항

원문에 수치가 없는 항목입니다. 아래 값은 **설계자의 가정**이며 확정된 비즈니스 결정이 아닙니다. 값이 바뀌면 `DEFAULT_POINTS_POLICY`와 domain.md 표만 고치면 됩니다.

| 항목 | 원문 | 가정한 값 | 가정 이유 |
| --- | --- | --- | --- |
| 기본 적립률 | "1%" | 1% (100bp) | **원문 확정** |
| 쿠폰 주문 (일반 등급) | "좀 줄여" | 0.5% (50bp) | "좀"을 기본의 절반으로 해석. 줄어드는 폭이 눈에 보이면서 0이 되지는 않는 값 |
| VIP (쿠폰 없음) | "더 많이" | 2% (200bp) | 기본의 2배. 일반 정수 배수라 계산·검증이 쉽다 |
| VIP + 쿠폰 | 언급 없음 | 1% (100bp) | 쿠폰 감산(절반)을 VIP 요율에도 똑같이 적용한 값(2% × 1/2). 일반·쿠폰 없음과 우연히 같다 |

요청자가 확인해야 할 질문:
1. 쿠폰 주문 요율 0.5%, VIP 요율 2%, VIP+쿠폰 요율 1%가 맞는가? 아니면 원하는 값은?
2. "결제 금액"에 **배송비를 포함**하는가? (가정: 포함 — domain.md의 결제 금액 `total` 용어를 따름. 상품 금액 기준이면 `subtotal − discount`로 바뀐다)
3. "쿠폰을 쓴 주문"을 `discount > 0`으로 판정해도 되는가? (쿠폰 계산 0003이 미구현이라 현재 할인은 쿠폰뿐이라는 전제. 쿠폰 외 할인이 생기면 별도 입력 필요)
4. VIP이면서 쿠폰을 쓴 경우에도 VIP 우대를 유지(가정: 1%)하는가, 아니면 쿠폰 사용 시 등급 무관 고정 요율인가?
5. 1% 미만 소수는 **내림**(가정)이 맞는가? 반올림이면 99원 주문이 1포인트가 된다.
6. 환불·취소 시 적립 회수는 별도 태스크로 진행해도 되는가?
