# 0030 — 포인트 적립 — PRD

- **이슈:** #1
- **역할 분리:** on
- **문제:** 주문해도 포인트가 쌓이지 않는다. 원문(`request.md`)은 방향만 주고 숫자를 주지 않는다. "쿠폰을 쓴 주문은 적립을 **좀** 줄여", "VIP는 **더 많이**"에 수치가 없고, 현재 코드·도메인 문서에는 쿠폰(0003 미구현)·VIP(회원 등급) 개념이 아예 없다.
- **목표:** 결제 금액(`total`)과 주문 조건(쿠폰 사용 여부·회원 등급)으로 적립 포인트(정수)를 계산하는 순수 함수를 `src/pricing/points.ts`에 만든다. 모호한 부분은 규칙으로 못 박아 `domain.md`에 쓰고, **수치는 상수 표 하나**에 모아 요청자가 한 곳만 고치면 되게 한다.
- **비목표:** 포인트 잔액·사용(차감)·만료·취소/환불 시 회수, 주문 모듈과의 연결(주문 모듈 없음), 쿠폰 계산 자체(0003), 회원 관리·등급 판정(등급은 호출자가 넘긴다), `priceCart`·`PriceBreakdown` 변경.

## 원문에 없어 가정한 값 — 사람 확인 필요

원문 방향(쿠폰 사용 < 기본 1% < VIP)을 거스르지 않는 선에서 정한 **설계 결정**이다. 원문이 확정한 값은 "기본 1%" 하나뿐이다.

| 구분 | 적립률 | 근거 |
| --- | --- | --- |
| 일반 회원 · 쿠폰 미사용 | **1%** | 원문 확정 |
| 일반 회원 · 쿠폰 사용 | 0.5% (가정) | "좀 줄여" → 기본의 절반 |
| VIP · 쿠폰 미사용 | 2% (가정) | "더 많이" → 기본의 2배 |
| VIP · 쿠폰 사용 | 1% (가정) | 쿠폰 ×0.5, VIP ×2가 겹치면 곱해 ×1 |

그 밖에 원문에 없어 정한 규칙(근거는 sdd.md): ① 기준 금액은 배송비 포함 `total` ② 쿠폰 사용 여부는 `discount > 0`이 아니라 호출자가 넘기는 명시 플래그 ③ 정수 변환은 **내림** ④ 등급은 `"NORMAL" | "VIP"` 입력 ⑤ 0원·빈 주문은 0포인트(오류 아님), 음수·비정수는 `RangeError`.

## Acceptance

원문 문장별 대응 (괄호는 원문 문장):
- [ ] (결제 금액의 1%) 일반 회원·쿠폰 미사용 주문은 `total`의 1%다. `total` 100 → 1, 53,000 → 530. 기준은 상품 합계가 아니라 결제 금액이라 배송비를 포함한다 (상품 20,000 → `total` 23,000 → 230)
- [ ] (쿠폰을 좀 줄여) 같은 `total`·같은 등급에서 쿠폰 사용 적립이 미사용 적립보다 **작고** 0은 아니다 — 일반 100,000원: 미사용 1,000 / 사용 500, VIP 100,000원: 2,000 / 1,000. 숫자와 무관하게 `쿠폰 적립률 < 쿠폰 미사용 적립률`이 두 등급 모두에서 성립
- [ ] (VIP는 더 많이) 같은 `total`·같은 쿠폰 조건에서 VIP 적립이 일반보다 **크다** — 쿠폰 미사용 100,000원: 일반 1,000 / VIP 2,000, 쿠폰 사용 100,000원: 일반 500 / VIP 1,000
- [ ] (1포인트 단위, 정수) 반환값은 항상 0 이상의 안전한 정수이고 **내림**이다. `total` 99 → 0, 199 → 1, 일반·쿠폰 사용 199 → 0, 200 → 1. `Number.MAX_SAFE_INTEGER` 결제 금액도 부동소수 오차 없이 정확한 내림 값
- [ ] (쿠폰+VIP 동시) 쿠폰을 쓴 VIP 주문의 적립률은 규칙 표대로(1%)이고, 같은 조건의 일반·쿠폰 사용보다 크며 VIP·쿠폰 미사용보다 작다
- [ ] (코드 위치) `src/pricing/points.ts`가 `earnPoints`와 적립률 상수 표를 export하고(시그니처는 sdd.md), 적립률 숫자는 그 상수 표 한 곳에만 있다. `Won`·`assertWon`·`PriceBreakdown`을 재사용하고 `priceCart`는 바꾸지 않는다
- [ ] (연동) `priceCart` 결과를 그대로 `earnPoints`에 넘길 수 있다: 빈 장바구니 → 0, 20,000원 상품(`total` 23,000) → 230, 상품 20,000원·할인 5,000원·쿠폰 사용(`total` 18,000) → 90
- [ ] 결제 금액 0원(빈 주문 포함)은 어떤 조건에서도 0포인트이며 오류가 아니다
- [ ] 잘못된 입력은 `RangeError`: 음수·비정수·`NaN`·`Infinity`·안전 정수 초과 `total`, `"NORMAL"`·`"VIP"` 이외 등급
