# 0030 — 포인트 적립 — PRD

- **이슈:** #1
- **문제:** 주문 시 적립해 줄 포인트를 계산하는 규칙이 없다. 요청이 "쿠폰을 쓰면 좀 줄여라", "VIP는 더 많이"처럼 정도가 정해지지 않아, 요청자에게 질문해 아래 규칙을 확정했다(2026-10-07).
- **목표:** `priceCart` 결과(`PriceBreakdown`)와 회원 등급으로 적립 포인트(정수)를 계산하는 순수 함수를 `src/pricing/points.ts`에 만든다. 규칙은 [domain.md](../../../context/domain.md)의 "포인트 적립 규칙 (0030)"이 단일 소스다.
- **확정 규칙 요약:**
  - 적립 기준 금액 = `subtotal − discount` (배송비 제외)
  - 기본 적립률 1%, VIP 2%(2배)
  - `discount > 0`이면 쿠폰을 쓴 주문으로 보고 적립률을 절반으로 줄인다. VIP 2배를 먼저 적용한 뒤 절반(VIP+쿠폰 = 1%, 일반+쿠폰 = 0.5%)
  - 1포인트 미만은 버린다(내림)
- **비목표:** 포인트 잔액·사용·환불 시 회수, 쿠폰 계산(0003), 회원 등급 판정(등급은 입력으로 받는다), 영속화.

## Acceptance
- [x] 일반 회원·쿠폰 없음: 적립 기준 금액의 1%를 내림한 정수를 돌려준다 (경계값 99원 → 0, 100원 → 1)
- [x] VIP·쿠폰 없음: 2%를 적용한다 (경계값 49원 → 0, 50원 → 1)
- [x] 쿠폰 사용(`discount > 0`): 일반 0.5%, VIP 1%를 적용한다 (경계값 일반 199원 → 0, 200원 → 1)
- [x] 적립 기준은 `subtotal − discount`이고 배송비·`total`은 쓰지 않는다 (배송비가 달라도 결과가 같음)
- [x] 빈 장바구니(전부 0)는 0포인트다
- [x] 입력 검증: 금액이 0 이상의 정수가 아니거나 `discount > subtotal`이거나 알 수 없는 등급이면 `RangeError`로 거부한다
- [x] 결과는 항상 0 이상의 정수다 (부동소수점 오차 없음 — 정수 연산만 사용)
- [x] `pnpm check` ALL PASS
