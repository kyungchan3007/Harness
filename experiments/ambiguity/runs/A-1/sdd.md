# 0030 — 포인트 적립 — SDD

- **접근:** 포인트 적립을 단순 함수로 구현합니다. 입력은 `{ total, discount, isVip }` 객체이고, 반환값은 정수 포인트입니다. 적립률과 배율을 매개변수화하여 도메인 변화에 쉽게 대응합니다.

## 적립률 계산

### 1. 기본 적립률
```
points = floor(total × 0.01)
```
- `total`: 결제 금액 (원, 정수)
- 결과: 1포인트 단위의 정수

### 2. 쿠폰 사용 시 감소
- 조건: `discount > 0`
- 적립률 감소: 50% (기본 1% → 0.5%)
```
points_with_coupon = floor(total × 0.005)
```

### 3. VIP 회원 추가 적립
- 조건: `isVip = true`
- 적립률 배율: 1.5배
- 쿠폰 미사용: `floor(total × 0.015)`
- 쿠폰 사용: `floor(total × 0.0075)`

## 제약사항

- `total`과 `discount`는 항상 0 이상의 정수 (domain.md 규칙)
- 포인트는 음수가 될 수 없음 (결과는 `max(0, calculated)`)

## 대안·트레이드오프

### 1. 적립률 계산 방식

| 방안 | 장점 | 단점 |
| --- | --- | --- |
| `Math.floor` | 단순, 명확, 저렴 | 항상 내림 (사용자 입장에선 손해) |
| `Math.round` | 가장 가까운 정수 | 일관성 없음 (5 근처에서 예측 어려움) |

**선택: `Math.floor`** — 도메인 규칙상 원/포인트는 항상 정수이고, 내림 방식이 명확하기 때문입니다.

### 2. VIP 배율 적용 위치

| 방안 | 장점 | 단점 |
| --- | --- | --- |
| 기본률에만 배율 (1% → 1.5%) | 심플 | 쿠폰 조건이 분리되어 복잡 |
| 최종 계산 후 배율 | 하나의 배율로 통일 | 0.5% × 1.5 = 0.75% 정확도 이슈 |
| 조건부 기본률 설정 (SDD 현재) | 각 경우마다 명확한 계산식 | 코드가 조금 길어짐 |

**선택: 조건부 기본률** — 각 케이스가 명확하고 테스트하기 쉽습니다.

- **대안·트레이드오프:**
  1. 적립률 계산: `Math.floor`로 선택 (명확하고 저렴)
  2. VIP 배율: 조건부 기본률로 선택 (각 케이스 명확)

- **검증 계획:**
  1. 단위 테스트: 6개 케이스 그룹 (기본, 쿠폰, VIP, VIP+쿠폰, 엣지 케이스 ×2)
  2. 정수 반올림: `Math.floor` 동작 확인 (999원 케이스)
  3. 토글 검증: `discount=0` vs `discount=1` 명확한 차이
  4. 확장성: 적립률 상수화로 향후 변경 용이성 확인
