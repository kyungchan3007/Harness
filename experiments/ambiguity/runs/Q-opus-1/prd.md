# 0030 — 포인트 적립 — PRD

- **이슈:** #1
- **상태:** 질문 대기 (아래 "열린 질문"에 사람의 답이 오기 전에는 구현하지 않음)
- **문제:** 주문 시 포인트를 적립해 주는 계산이 없다.
- **목표:** 주문 금액·쿠폰 사용 여부·회원 등급을 받아 적립 포인트(정수)를 돌려주는 순수 함수를 `src/pricing/points.ts`에 만든다.
- **비목표(가정 — Q7에서 확인):** 포인트 잔액·원장 저장, 적립 시점(결제/구매확정), 취소·환불 시 회수, 포인트 사용(결제에 차감).

## 요청 원문

- 결제 금액의 1%를 포인트로 적립합니다.
- 쿠폰을 쓴 주문은 적립을 좀 줄여 주세요.
- VIP 회원은 더 많이 적립해 주세요.
- 포인트는 1포인트 단위(정수)입니다.
- 코드는 `src/pricing/points.ts`에 만들어 주세요.

## 열린 질문

저장소 현황: [domain.md](../../../context/domain.md)에 쿠폰은 "0003에서" 예정이고 아직 없음(`discount`는 숫자로만 받음). 회원·등급 개념은 코드·문서 어디에도 없음.

| # | 질문 | 왜 모호한가 | 선택지 예 |
| --- | --- | --- | --- |
| Q1 | 적립 기준 "결제 금액"은 무엇인가? | domain.md의 결제 금액(total)은 **배송비 포함**이다 | (a) `total` 그대로(배송비 포함) (b) `subtotal − discount`(배송비 제외) |
| Q2 | 1%가 정수로 안 떨어질 때 어떻게 자르나? | "정수"만 정해졌고 방향이 없다 | 내림(floor) / 반올림 / 올림 |
| Q3 | 쿠폰 사용 시 "좀 줄여"는 얼마인가? | 수치가 없다 | (a) 적립률 0.5% (b) 1%의 절반 등 비율 감소 (c) 고정 N포인트 차감 (d) 적립 0 |
| Q4 | "쿠폰을 쓴 주문"은 어떻게 판정하나? | 쿠폰 모듈(0003)이 아직 없다 | (a) `discount > 0`이면 쿠폰 사용 (b) 호출자가 `usedCoupon: boolean`을 따로 넘김 |
| Q5 | VIP는 "더 많이" 얼마인가? | 수치가 없다 | (a) 적립률 2% (b) 1.5배 (c) +N포인트 |
| Q6 | VIP가 쿠폰을 쓰면? | 두 규칙의 결합 순서가 없다 | (a) VIP율에 쿠폰 감소를 곱함 (b) 쿠폰 감소가 우선(VIP 혜택 없음) (c) VIP는 쿠폰 감소 면제 |
| Q7 | 범위가 "계산 함수"만인가? | "적립해 주는 기능"이 잔액 저장·취소 회수까지 뜻할 수 있다 | (a) 계산만(위 비목표 유지) (b) 잔액/원장까지 |
| Q8 | VIP 여부는 어떻게 받나? 등급이 VIP 하나뿐인가? | 회원 모델이 없다 | (a) `isVip: boolean` 입력 (b) `tier: "normal" \| "vip"` (등급 추가 여지) |
| Q9 | 상한·하한이 있나? (주문당 최대 적립, 최소 결제 금액) | 언급 없음 | 없음 / 있음(값) |
