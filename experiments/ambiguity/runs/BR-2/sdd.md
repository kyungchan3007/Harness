# 0030 — 주문 시 포인트 적립 — SDD

요구사항: [prd.md](prd.md)

## 설계

- **읽은 문서:** agents/context/domain.md (결제 금액 정의, 배송비·할인 규칙)

- **접근:** 순수 함수로 포인트 계산만 담당 (입력: 결제금액·VIP여부·쿠폰사용 → 출력: 정수포인트)
  - 기본 적립: paymentAmount × 0.01
  - 쿠폰 조정: couponUsed이면 × 0.5
  - VIP 조정: isVip이면 × 1.5
  - 정수 변환: Math.round() 사용

- **대안·트레이드오프:** 고정 비율(쿠폰 50%, VIP 1.5배) 선택 / Math.round() 선택 / 향후 필요 시 매개변수화 (범위 밖)
  - 고정값 이유: 간단함, 명확함, 첫 구현에 적합
  - round 이유: 표준적, 공정함(0.5 이상 올림)

- **파일 계획:** `src/pricing/points.ts` 신규 파일 (calculatePoints 함수), 테스트 별도

- **위험:** 반올림 경계값(예: 7.5→8)과 Order 모델 필드명 불일치 → 테스트·domain.md 기준 사용으로 대응

- **검증 계획:** 단위 테스트(기본·쿠폰·VIP·조합) + 경계값(0,1,999,1000,50000,100000) + 반올림검증(0.4~0.6) / Jest·pnpm check 통과 필수

## 계산 로직

### 함수 시그니처

```typescript
/**
 * 주문의 결제 금액을 기반으로 적립 포인트를 계산합니다.
 * 
 * @param paymentAmount 결제 금액(원) — domain.md의 total = subtotal - discount + shipping
 * @param isVip VIP 회원 여부 (기본값: false)
 * @param couponUsed 쿠폰 사용 여부 (기본값: false)
 * @returns 적립 포인트(정수)
 */
function calculatePoints(
  paymentAmount: number,
  isVip: boolean = false,
  couponUsed: boolean = false
): number
```

### 계산 순서

1. 기본 포인트: `paymentAmount × 0.01`
2. 쿠폰 적용: `couponUsed ? 포인트 × 0.5 : 포인트`
3. VIP 적용: `isVip ? 포인트 × 1.5 : 포인트`
4. 정수 변환: `Math.round(포인트)`

### 테스트 케이스

#### 기본 적립 (쿠폰 미사용, VIP 아님)
| 결제금액 | 예상 포인트 | 계산식 |
| --- | --- | --- |
| 0 | 0 | 0 × 0.01 = 0 |
| 100 | 1 | 100 × 0.01 = 1 |
| 999 | 10 | 9.99 → round = 10 |
| 10,000 | 100 | 10000 × 0.01 = 100 |
| 15,750 | 158 | 157.5 → round = 158 |

#### 쿠폰 적용 (VIP 아님)
| 결제금액 | 예상 포인트 | 계산식 |
| --- | --- | --- |
| 10,000 | 50 | (10000 × 0.01) × 0.5 = 50 |
| 15,750 | 79 | (157.5) × 0.5 = 78.75 → round = 79 |

#### VIP 회원 (쿠폰 미사용)
| 결제금액 | 예상 포인트 | 계산식 |
| --- | --- | --- |
| 10,000 | 150 | (10000 × 0.01) × 1.5 = 150 |
| 15,750 | 236 | (157.5) × 1.5 = 236.25 → round = 236 |

#### VIP + 쿠폰
| 결제금액 | 예상 포인트 | 계산식 |
| --- | --- | --- |
| 10,000 | 75 | (10000 × 0.01) × 0.5 × 1.5 = 75 |
| 15,750 | 118 | (157.5) × 0.5 × 1.5 = 118.125 → round = 118 |
