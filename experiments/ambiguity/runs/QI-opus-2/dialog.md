## 답이 필요한 질문

1. **적립 기준 금액:** 이 저장소의 규칙 문서(`domain.md`)는 "결제 금액"을 `상품 합계 − 할인 + 배송비`로 정의합니다. 배송비를 포함한 이 금액으로 적립하나요, 배송비를 뺀 `상품 합계 − 할인`으로 적립하나요?
2. **쿠폰을 쓰면 얼마나 줄이나요?** 예를 들어:
   - 적립률을 0.5%로 내림
   - 적립 포인트를 절반으로 줄임
   - 따로 줄이지 않음(쿠폰 할인이 이미 결제 금액에서 빠져 있으므로)
3. **"쿠폰을 쓴 주문"은 어떻게 구분하나요?** 쿠폰 기능은 아직 코드에 없습니다. 할인이 1원 이상이면 쿠폰 주문으로 보나요, 아니면 쿠폰 사용 여부를 따로 입력받나요? 할인 금액이 없는 쿠폰(예: 무료배송 쿠폰)도 적립을 줄이나요?
4. **VIP는 얼마나 더 적립하나요?** 예: 2%, 1%p 추가, 2배. 회원 등급은 일반과 VIP 두 가지뿐인가요?
5. **VIP 회원이 쿠폰을 쓰면 어떻게 계산하나요?** 예: VIP 적립률에 쿠폰 감액을 그대로 적용 / 쿠폰을 쓰면 VIP 혜택 없음.
6. **1포인트 미만은 어떻게 처리하나요?** 버림, 반올림, 올림 중 어느 것인가요? 계산 단계마다 정수로 맞추나요, 마지막에 한 번만 맞추나요?
7. **이번 작업 범위는 어디까지인가요?**
   - 적립 포인트를 계산하는 함수까지만 만드나요, 잔액 저장과 주문 취소 시 회수까지 하나요?
   - 적립 상한이나 최소 주문 금액이 있나요?
   - 결제 금액이 0원인 주문은 0포인트로 보면 되나요?

## 요청자

1. 적립 기준은 쿠폰 할인 후 상품 금액(subtotal − discount)입니다. 배송비는 빼고 계산합니다.
2. 쿠폰을 쓴 주문은 적립률을 절반으로 줄입니다 (1% → 0.5%).
3. 쿠폰을 썼는지는 priceCart 결과(PriceBreakdown)의 discount가 0보다 큰지로 판단합니다. 쿠폰 할인은 discount로 들어옵니다. 입력은 priceCart 결과(PriceBreakdown: subtotal·discount·shipping·total)와 회원 정보 { grade: "VIP" | "NORMAL" }입니다. 함수 이름은 자유입니다.
4. VIP는 적립률 2배입니다 (1% → 2%). 회원 정보는 { grade: "VIP" | "NORMAL" } 형태로 따로 받습니다. 입력은 priceCart 결과(PriceBreakdown: subtotal·discount·shipping·total)와 회원 정보 { grade: "VIP" | "NORMAL" }입니다. 함수 이름은 자유입니다.
5. VIP가 쿠폰을 쓰면 VIP 2배를 먼저 적용하고 쿠폰으로 절반을 줄입니다 (2% → 1%).
6. 1포인트 미만은 버립니다(내림).
7. 그 부분은 따로 정한 게 없으니 알아서 정해 주세요.

## AI

답변대로 포인트 적립 기능을 `src/pricing/points.ts`에 만들었습니다. `pnpm check`는 ALL PASS(테스트 116개, 이번에 11개 추가)이고, 기록을 마친 뒤 한 번 더 돌려도 통과했습니다. 커밋과 이슈 동기화는 아직 하지 않았습니다.

**계산 방식**
- 함수는 `calculatePoints(priceCart 결과, { grade })`입니다. 결과는 0 이상의 정수입니다.
- 적립 기준은 `subtotal − discount`이고 배송비는 넣지 않습니다.
- 적립률은 일반 1%, VIP 2%입니다. `discount`가 0보다 크면 쿠폰 주문으로 보고 적립률을 절반으로 줄입니다(일반 0.5%, VIP 1%).
- 1포인트 미만은 버리고, 정수로 맞추는 건 마지막에 한 번만 합니다. 예를 들어 VIP가 150원을 결제하면 3포인트입니다. 1%를 먼저 버림한 뒤 2배를 하면 2포인트가 되는데, 그렇게 되지 않습니다.
- 적립률은 정책 객체로 분리해 두어서 나중에 비율이 바뀌면 바꿔 넣을 수 있습니다.

**7번(범위)은 이렇게 정했습니다.** 다르게 하길 원하시면 알려 주세요.
- 이번에는 적립할 포인트를 계산하는 것까지만 합니다. 잔액 저장, 포인트 사용, 주문 취소 시 회수, 만료는 하지 않았습니다.
- 적립 상한과 최소 주문 금액은 없습니다.
- 기준 금액이 0원이면 0포인트입니다.
- 잘못된 입력은 오류(`RangeError`)를 냅니다. 음수나 소수 금액, 할인이 상품 합계보다 큰 경우, VIP·NORMAL이 아닌 등급이 여기에 해당합니다.

**문서 기록**
- 규칙 문서(`domain.md`)에 "포인트 적립 규칙 (0030)" 절을 추가했습니다.
- `prd.md`에 질문과 답을 표로 남기고 완료 조건을 모두 체크했습니다.
- `sdd.md`, `trace.md`, `JOURNAL.md`를 갱신하고 `TASKS.md`의 0030을 `done`으로 바꿨습니다.

**작업 중 확인한 것**
- 처음 쓴 `prd.md`의 제목을 `## Acceptance (질문 답변 후 확정)`으로 붙였더니, 수정 전 검사 훅이 완료 조건 절을 찾지 못해 `domain.md` 수정을 막았습니다. 제목을 `## Acceptance`로 바꾸니 통과했고, 이 일은 trace와 JOURNAL에 남겼습니다.
