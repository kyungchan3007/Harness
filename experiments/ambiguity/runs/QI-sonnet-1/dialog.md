## AI

요구사항이 모호해서 구현은 하지 않았습니다. 대신 `agents/intent/specs/0030-points/`에 `prd.md`, `sdd.md`, `trace.md`를 만들고, `TASKS.md`에 0030을 "답 대기"로 등록했습니다. `src/`는 건드리지 않았고 `pnpm check`도 실행하지 않았습니다. 커밋도 하지 않았습니다.

"쿠폰을 쓴 주문"과 "VIP 회원"은 이 저장소에 아직 정의가 없습니다. 쿠폰은 0003이 미구현이고, 회원·등급 개념은 코드에도 문서에도 없습니다. "좀 줄여", "더 많이"는 수치가 없어서 구현하면 임의의 비율을 정하게 됩니다.

답을 주셔야 할 질문입니다(선택지와 함께 `prd.md`에도 적어 두었습니다).

1. **쿠폰 사용 판별:** `discount > 0`이면 쿠폰 사용으로 볼까요, 별도 입력(`couponUsed`)으로 받을까요, 아니면 0003 이후로 미룰까요?
2. **쿠폰 사용 시 적립률:** 얼마인가요? (예: 0.5%)
3. **VIP 표현과 적립률:** `isVip: boolean`이면 충분한가요, 등급이 필요한가요? 적립률은 얼마인가요? (예: 2%)
4. **쿠폰을 쓴 VIP 주문:** 적립률은 어떻게 정할까요? (VIP 비율 그대로 / 쿠폰 감소 우선 / 두 효과 곱 / 직접 지정)
5. **적립 기준 금액:** 배송비를 포함한 `total`로 할까요, 배송비를 뺀 `subtotal − discount`로 할까요?
6. **소수점 처리:** 내림, 반올림, 올림 중 무엇인가요? (예: 12,350원 × 1% = 123.5포인트)
7. **0포인트 허용:** 빈 장바구니나 100원 미만 결제처럼 적립이 0이 되는 경우 그대로 0을 반환해도 되나요?

답을 주시면 `domain.md`에 포인트 규칙을 먼저 반영하고, 이어서 `sdd.md`, `src/pricing/points.ts`와 테스트, `pnpm check` 순서로 진행하겠습니다.

## 요청자

1. 쿠폰을 썼는지는 priceCart 결과(PriceBreakdown)의 discount가 0보다 큰지로 판단합니다. 쿠폰 할인은 discount로 들어옵니다. 입력은 priceCart 결과(PriceBreakdown: subtotal·discount·shipping·total)와 회원 정보 { grade: "VIP" | "NORMAL" }입니다. 함수 이름은 자유입니다.
2. 쿠폰을 쓴 주문은 적립률을 절반으로 줄입니다 (1% → 0.5%).
3. 회원 정보는 { grade: "VIP" | "NORMAL" } 형태로 따로 받습니다. VIP는 적립률 2배입니다 (1% → 2%). 입력은 priceCart 결과(PriceBreakdown: subtotal·discount·shipping·total)와 회원 정보 { grade: "VIP" | "NORMAL" }입니다. 함수 이름은 자유입니다.
4. VIP가 쿠폰을 쓰면 VIP 2배를 먼저 적용하고 쿠폰으로 절반을 줄입니다 (2% → 1%).
5. 적립 기준은 쿠폰 할인 후 상품 금액(subtotal − discount)입니다. 배송비는 빼고 계산합니다.
6. 1포인트 미만은 버립니다(내림).
7. 그 부분은 따로 정한 게 없으니 알아서 정해 주세요.

## AI

포인트 적립 기능을 `src/pricing/points.ts`에 구현했고, 포인트 단위 테스트 12개를 추가했습니다. 최종 `pnpm check`가 ALL PASS(전체 테스트 117개)입니다. 커밋과 PR은 요청하지 않으셔서 만들지 않았고, 변경은 작업 트리에만 있습니다.

- **함수:** `calculatePoints(breakdown, { grade })`입니다. 적립률은 NORMAL 1%, 쿠폰 사용 시 0.5%, VIP 2%, VIP에 쿠폰 사용 시 1%입니다. 쿠폰 사용 여부는 `discount > 0`으로 판단합니다.
- **계산:** 기준 금액은 `subtotal − discount`(배송비 제외)이고, 1포인트 미만은 내림합니다. 소수 오차를 피하려고 정수 연산으로 계산합니다.
- **문서:** 규칙을 `domain.md`에 먼저 반영했고, `architecture.md`, prd·sdd·trace, `TASKS.md`, `JOURNAL.md`를 갱신했습니다.
- **Q7(0포인트):** 말씀하신 대로 제가 정했습니다. 0포인트가 나와도 거부하지 않고 0을 반환합니다. 이 결정은 prd에 "에이전트 결정"으로 표시해 두었으니 바꾸고 싶으면 알려 주세요.
- **추가한 입력 검증:** 비정수나 음수, 할인이 상품 합계보다 큰 경우, 곱셈 결과가 안전 정수를 넘는 경우를 `RangeError`로 거부합니다.
- **알려진 한계:** `total`을 쓰지 않아서 `total`이 다른 필드와 맞지 않는 입력은 검사하지 않습니다.
