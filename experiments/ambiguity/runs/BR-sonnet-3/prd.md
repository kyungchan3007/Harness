# 0030 — 포인트 적립 — PRD

- **이슈:** #1
- **역할 분리:** on
- **문제:** 주문을 해도 포인트가 쌓이지 않는다. 원문(이슈 #1)은 "결제 금액의 1%", "쿠폰 쓴 주문은 좀 줄여", "VIP는 더 많이", "1포인트 단위(정수)"라고만 말하고, 줄이는 폭·늘리는 폭·소수 처리 방식 같은 정량 기준이 없다.
- **목표:** 결제 금액(total)·쿠폰 사용 여부·VIP 여부를 입력으로 받아 적립 포인트(0 이상 정수)를 돌려주는 순수 함수를 `src/pricing/points.ts`에 만든다. 적립률은 코드의 상수 한 곳에서 바꿀 수 있다. 규칙은 [domain.md](../../context/domain.md)의 "포인트 적립 규칙 (0030)"이 단일 소스다.
- **비목표:** 쿠폰 계산·쿠폰 사용 여부 판별(0003), VIP 등급 판별·회원 모델, 포인트 잔액 저장·사용(차감)·소멸·환불 시 회수, `priceCart`/`Cart` 수정, 영속화, HTTP API.

## 확정 (원문에 있음)
- 기본 적립률은 결제 금액의 1%.
- 쿠폰을 쓴 주문은 기본보다 적게, VIP는 기본보다 많이 적립한다 (방향만 확정).
- 포인트는 1포인트 단위의 정수.
- 코드 위치는 `src/pricing/points.ts`.

## 열린 질문 / 가정 (원문에 없어 잠정 결정한 항목 — 사용자 확인 필요)
아래 값은 **확정된 사실이 아니라 잠정 제안**이다. 사용자가 다른 값을 정하면 상수 한 곳(`DEFAULT_POINT_POLICY`)과 domain.md 표만 고치면 된다.

| # | 원문 표현 / 빈칸 | 잠정 결정 | 대안 |
| --- | --- | --- | --- |
| Q1 | "쿠폰을 쓴 주문은 적립을 좀 줄여" — 얼마나? | 쿠폰 사용 시 적립률을 **절반** (일반 0.5%) | 0.7%, 0% 등 |
| Q2 | "VIP 회원은 더 많이" — 얼마나? | VIP 적립률 **2%** (일반의 2배) | 1.5%, 3% 등 |
| Q3 | 쿠폰 + VIP 조합 | VIP 적립률에 쿠폰 감산을 똑같이 적용 → **1%** (VIP 2%의 절반) | VIP 2% 유지, 쿠폰 우선 0.5% 등 |
| Q4 | 1%가 정수가 아닐 때 | **내림**(floor). 예: 12,345원 → 123.45 → 123 | 반올림, 올림 |
| Q5 | "결제 금액" 범위 | domain.md의 `total`(= 상품 합계 − 할인 + 배송비) **그대로**. 배송비 포함 | 배송비 제외 |
| Q6 | 쿠폰·VIP·total이 코드에 있는가 | 확인 결과 **VIP·쿠폰 사용 여부는 코드에 없음**. `total`만 `priceCart().total`에 있음. 그래서 셋 모두 함수 입력으로 받는다 | - |
| Q7 | total 0원 | 0포인트 (오류 아님) | - |
| Q8 | total이 음수·소수·NaN·Infinity | `RangeError` (기존 `assertWon` 재사용, 기존 금액 규칙과 일치) | 0으로 보정 |
