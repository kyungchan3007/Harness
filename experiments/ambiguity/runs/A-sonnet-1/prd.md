# 0030 — 포인트 적립 — PRD

- **이슈:** #1
- **문제:** 주문해도 적립되는 포인트가 없다. 요청은 "결제 금액의 1%, 쿠폰 쓰면 좀 줄이고, VIP는 더 많이, 1포인트 단위"인데 **"좀"·"더"의 수치가 없고**, 쿠폰(0003)과 회원 등급은 이 저장소에 아직 없는 개념이다.
- **목표:** 결제 금액·회원 등급·쿠폰 사용 여부로 적립 포인트(정수)를 계산하는 순수 함수를 `src/pricing/points.ts`에 만든다. 규칙은 [domain.md](../../../context/domain.md) "포인트 적립 규칙 (0030)"이 단일 소스다.
- **비목표:** 쿠폰 계산(0003), 회원·등급 관리, 포인트 잔액·사용·소멸·환불 시 회수, 영속화, `priceCart` 결과에 포인트를 합치는 것.

## 가정 (요청에 없어 채운 값 — 확정 필요)

요청 원문에 수치가 없는 부분이다. 아래는 에이전트가 정한 **임시 값**이며 사용자 확인 전까지 미확정이다. 값은 `DEFAULT_POINT_POLICY` 한 곳에만 있어 바꾸기 쉽다.

| 가정 | 값 | 근거 |
| --- | --- | --- |
| 적립 기준 금액 | 결제 금액 `total` (배송비 포함) | 요청의 "결제 금액" = domain.md 용어 `total` 그대로 |
| 일반 회원 | 1% | 요청 |
| 일반 회원 + 쿠폰 | 0.5% | "좀 줄여" → 절반으로 가정 |
| VIP | 2% | "더 많이" → 2배로 가정 |
| VIP + 쿠폰 | 1% | 요청에 없는 조합. 쿠폰 감산(절반)을 VIP에도 같은 방식으로 적용 |
| 소수 처리 | 내림 | "1포인트 단위(정수)"만 있고 반올림 방식 없음. 과지급을 피하는 쪽 |
| 쿠폰 사용 판정 | 호출자가 넘기는 `couponUsed` 불리언 | `discount > 0`으로 추정하면 쿠폰 외 할인이 생길 때 틀림 |
