# 0030 — 포인트 적립 기능 — SDD

요구사항: [prd.md](prd.md)

## 설계

- **읽은 문서:** AGENTS.md, harness/loop.md, context/architecture.md, context/domain.md, 0002-cart-pricing/{prd,sdd}.md
- **접근:**
  - `src/pricing/points.ts`: 순수 함수 `calculatePoints(total, options)` 구현
  - 적립 계산 순서: (기본값) × (쿠폰 감소) × (VIP 증가) = 최종 포인트
  - 옵션 기본값: `hasCoupon = false`, `isVip = false`
  - 모든 중간값은 `number` 정수로 계산하고, 최종 결과를 정수로 내림 처리
  - 입력값 유효성: `total ≥ 0` (음수 금액 불가)
  
- **적립 규칙 상세:**
  - 기본 적립률: 1% (`total * 0.01`)
  - 쿠폰 감소: 70% 적용 (`× 0.7`)
  - VIP 증가: 150% 적용 (`× 1.5`)
  - 공식: `basePoints × (hasCoupon ? 0.7 : 1.0) × (isVip ? 1.5 : 1.0)`
  
- **대안·트레이드오프:**
  - 쿠폰/VIP 배수를 하드코딩 vs 옵션으로 받기: 하드코딩이 도메인 규칙과 맞고 테스트 추적이 쉽다. → 채택.
  - 소수점 처리: `Math.floor()` (내림) vs `Math.round()` (반올림): 규칙에서 "1포인트 단위"이고 기본 1%는 정수가 아닐 가능성이 크다 → 내림 선택이 공정.
  - 음수 금액 처리: 예외 vs 0반환: 금액은 항상 음이 아니므로 단위 테스트로만 검증, 입력 경계에서 위험할 시 거부.
  - 브랜드 타입: 이전에 `Won` 도입을 보류했으므로 이번도 `number` 유지.
  
- **파일 계획:** 
  - `src/pricing/points.ts`: `calculatePoints()` 함수 + 테스트
  - `agents/context/domain.md`: 포인트 섹션 추가 (용어, 적립 규칙, 회원 등급)
  
- **위험:**
  - 대규모 금액에서 부동소수점 오차: `1000000 * 0.01 * 0.7 * 1.5` 계산 결과가 정확한지 확인 필요
  - 쿠폰과 VIP 중복 적용 여부: 요구사항에서 "또는"이 아닌 조합이므로 곱셈으로 처리
  
- **검증 계획:**
  - 기본 적립 테스트: 1%, 10%, 100% 단위 금액
  - 쿠폰만: 적립의 70% 확인
  - VIP만: 적립의 150% 확인
  - 쿠폰+VIP: 적립의 105% 확인
  - 경계값: 0원, 1원, 50,000원, 999,999원
  - 부동소수점 오차: 내림 후 정수임을 확인
  - `pnpm check` 통과
