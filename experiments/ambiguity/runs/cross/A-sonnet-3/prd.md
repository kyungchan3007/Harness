# 0030 — 포인트 적립 — PRD

- **이슈:** #1
- **문제:** 주문해도 포인트가 쌓이지 않는다. 요청 원문은 "결제 금액의 1%", "쿠폰 쓴 주문은 적립을 좀 줄이고", "VIP는 더 많이", "1포인트 단위(정수)"인데, **줄이고/늘리는 정도와 몇 가지 경계가 정해져 있지 않다.** 도메인 문서에는 VIP·쿠폰 사용 개념도 아직 없다.
- **목표:** 결제 금액과 주문 조건(쿠폰 사용 여부·VIP 여부)으로 적립 포인트를 계산하는 순수 함수를 `src/pricing/points.ts`에 만든다. 규칙은 [domain.md](../../context/domain.md)의 "포인트 적립 규칙"에 먼저 고정한다.
- **비목표:** 포인트 잔액·사용(결제 시 차감)·소멸·취소 시 회수, 회원 등급 모델, 쿠폰 계산(0003), `priceCart`에 적립 연결, 영속화.

## 요청에서 정해지지 않아 가정한 것 (사용자 확인 필요)

원문이 수치를 주지 않은 빈칸이다. 아래 값은 **잠정**이며 domain.md에도 "잠정"으로 표시한다. 값만 바꾸면 되도록 정책 객체로 주입한다.

| 빈칸 | 가정 | 이유 |
| --- | --- | --- |
| 적립 기준 금액 | 결제 금액(`total`, 배송비 포함) | domain.md 용어 "결제 금액"을 그대로 따름. 배송비를 뺄지는 미정 |
| 쿠폰 사용 시 | 0.5% (기본의 절반) | "좀 줄여"의 수치 없음 |
| VIP | 2% (기본의 2배) | "더 많이"의 수치 없음 |
| VIP + 쿠폰 | 1% | 원문에 조합 규칙 없음. 표의 한 칸으로 따로 둠 |
| 소수 처리 | 소수점 이하 버림 | "정수 단위"만 있고 반올림 방식 없음. 버림이 과다 적립이 없는 안전한 쪽 |
| "쿠폰 사용" 판정 | 호출자가 `couponUsed`로 명시 | 쿠폰 모듈(0003)이 없고, `discount > 0`으로 추정하면 다른 할인과 섞임 |
