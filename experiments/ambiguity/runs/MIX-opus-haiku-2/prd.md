# 0030 — 포인트 적립 — PRD

- **이슈:** #1
- **문제:** 주문 시 포인트를 적립해 주는 기능이 없다.
- **목표:** `priceCart` 결과(`PriceBreakdown`)와 회원 정보(`{ grade: "VIP" | "NORMAL" }`)로 적립 포인트(0 이상 정수)를 계산하는 순수 함수를 `src/pricing/points.ts`에 만든다. 규칙은 [domain.md 포인트 적립 규칙](../../context/domain.md#포인트-적립-규칙-0030)이 단일 소스다.
- **비목표:** 포인트 잔액·원장 저장, 포인트 사용(결제 차감), 적립 취소·소멸, 쿠폰 할인액 계산 자체(0003), 회원 정보 조회.

## 확정된 요구사항 (요청자 답변, 2026-10-07)

| # | 질문 | 결정 | 출처 |
| --- | --- | --- | --- |
| Q1 | 적립 기준 금액 | `subtotal − discount`. 배송비 제외. 원문의 "결제 금액"은 domain.md의 `total`이 **아니라** 이 값 | 요청자 |
| Q2 | 소수점 처리 | 1포인트 미만 버림(내림) | 요청자 |
| Q3 | 쿠폰 주문 감소폭 | 적립률 절반 (1% → 0.5%) | 요청자 |
| Q4 | 쿠폰 사용 판단 | `PriceBreakdown.discount > 0` | 요청자 |
| Q5 | 쿠폰 할인액 차감 + 적립률 절반 이중 적용 여부 | **둘 다 적용한다.** Q1(기준에서 할인액 차감)과 Q3(적립률 절반)을 요청자가 각각 따로 지정했으므로 둘 중 하나를 빼면 어느 한 답을 어기게 된다 | 위임 → 에이전트 결정 |
| Q6 | VIP 적립률 | 2배 (1% → 2%) | 요청자 |
| Q7 | 회원 정보 | `{ grade: "VIP" \| "NORMAL" }`을 별도 인자로 받음. 등급은 두 가지뿐 | 요청자 |
| Q8 | VIP + 쿠폰 | VIP 2배 먼저, 그다음 쿠폰 절반 (2% → 1%) | 요청자 |
| Q9 | 버림 시점 | **마지막에 한 번만** 버린다. 적립률은 정수 bp(1% = 100bp)로 정확히 계산하므로 중간 단계에서 소수가 생기지 않는다 | 위임 → 에이전트 결정 |
| Q10 | 상한·0원 | **상한 없음.** 기준 금액 0(빈 장바구니·전액 할인)이면 0P. 요청에 상한 언급이 없어 임의 수치를 만들지 않음 | 위임 → 에이전트 결정 |

에이전트가 정한 Q5·Q9·Q10은 요청자가 바꾸면 domain.md 규칙 1·6·7만 고치면 된다.

**후속 확인 (2026-10-07):** 문서 확정 후 원문 "결제 금액"이 domain.md `total`(배송비 포함)과 다르다는 점을 다시 확인 요청했고, 요청자는 "따로 정한 게 없으니 알아서 정해 달라"고 답했다. Q1 답(`subtotal − discount`, 배송비 제외)이 이미 명시돼 있으므로 **그대로 유지**한다. 원문 "결제 금액" 표현은 domain.md 용어 "적립 기준 금액"으로 해석을 고정한다.
