# 0030 — 포인트 적립 — PRD

- **이슈:** #1
- **문제:** 주문해도 포인트가 쌓이지 않는다. 요청에 "쿠폰 쓰면 좀 줄여라", "VIP는 더 많이"만 있고 수치가 없어, 그대로 구현하면 임의 수치가 도메인 규칙으로 굳는다.
- **목표:** 결제 금액(`total`)의 1%를 정수 포인트로 적립하는 순수 함수를 `src/pricing/points.ts`에 만든다. 쿠폰 사용 주문은 적게, VIP는 많이 적립한다. 수치는 정책 객체로 주입할 수 있게 하고, 규칙은 `domain.md`에 문서화한다.
- **비목표:** 포인트 사용(차감)·잔액·만료, VIP 등급 판정, 쿠폰 계산(0003), 주문 상태와 연동.

## 요청에서 정해지지 않은 것 — 잠정 가정 (사용자 확인 필요)

| 빈칸 | 잠정 가정 | 이유 | 바꾸는 법 |
| --- | --- | --- | --- |
| 적립 기준 금액 | `total` (domain.md의 결제 금액, 배송비 포함) | 요청이 "결제 금액"이라 했고 domain.md가 그 용어를 `total`로 정의함 | 배송비를 빼려면 기준을 `total − shipping`으로 |
| 쿠폰 사용 주문 요율 | 0.5% (기본의 절반) | "좀 줄여" — 수치 없음 | `PointPolicy.couponRateBp` |
| VIP 요율 | 2% (기본의 2배) | "더 많이" — 수치 없음 | `PointPolicy.vipRateBp` |
| VIP + 쿠폰 | 1% (VIP 요율의 절반 = 비VIP 기본과 같음) | 두 규칙이 겹칠 때 정의 없음 | `PointPolicy.vipCouponRateBp` |
| 쿠폰 사용 판정 | 호출자가 `couponUsed`로 넘긴다 | 쿠폰 모듈(0003)이 아직 없고, `discount > 0`은 쿠폰 외 할인과 구분 못 함 | - |
| 소수점 처리 | 내림 | 1포인트 단위(정수). 회사가 손해 보지 않는 쪽 | `Math.floor` 한 곳 |
| 요율 단위 | 만분율(bp, 정수). 1% = 100bp | 부동소수점 오차 방지 | - |

## Acceptance
- [ ] 기본 적립은 결제 금액의 1%를 내림한 정수 (예: 12,345원 → 123P)
- [ ] 쿠폰 사용 주문은 0.5%, VIP는 2%, VIP+쿠폰은 1% (잠정 — 위 표)
- [ ] 결과는 항상 0 이상의 정수. 결제 금액 0원(빈 장바구니)은 0P
- [ ] 결제 금액이 잘못된 값(음수·소수·비정수)이면 `RangeError`
- [ ] 요율은 `PointPolicy`로 주입 가능, 기본값은 `DEFAULT_POINT_POLICY`
- [ ] 규칙을 `agents/context/domain.md`에 문서화 (잠정 표기 포함)
- [ ] 경계값 테스트 (내림 경계, 0원, 큰 금액에서 정수 유지)
- [ ] `pnpm check` ALL PASS
- [ ] 사용자에게 잠정 가정 확인 요청 (수치·기준 금액이 확정되면 domain.md의 "잠정" 표기를 지운다)
