# 0030 — 포인트 적립 — PRD

- **이슈:** #1
- **문제:** 주문 시 포인트 적립 규칙이 없다. 첫 요청은 "결제 금액의 1%, 쿠폰 주문은 좀 줄이고, VIP는 더 많이, 정수 포인트"라서 수치·기준이 비어 있었다. 질문 Q1~Q9에 요청자가 답해 규칙을 확정했다(아래).
- **목표:** `PriceBreakdown`과 회원 등급으로 적립 포인트를 계산하는 순수 함수를 `src/pricing/points.ts`에 만들고, 규칙을 [domain.md](../../context/domain.md#포인트-적립-규칙-0030)에 단일 소스로 추가한다.
- **비목표:** 포인트 잔액·원장 저장, 포인트 사용(결제 차감), 주문 취소 시 회수, 적립 시점 처리, 쿠폰 계산 자체(0003).

## 요청 원문

- 결제 금액의 1%를 포인트로 적립합니다.
- 쿠폰을 쓴 주문은 적립을 좀 줄여 주세요.
- VIP 회원은 더 많이 적립해 주세요.
- 포인트는 1포인트 단위(정수)입니다.
- 코드는 `src/pricing/points.ts`에 만들어 주세요.

## 질문과 답 (2026-10-08 요청자 답변)

| # | 질문 | 답 |
| --- | --- | --- |
| Q1 | 적립 기준 금액 | **subtotal**(쿠폰 할인 전 상품 합계). 배송비 제외, 할인 차감 안 함. 요청 원문의 "결제 금액"을 이렇게 해석한다 |
| Q2 | 끝수 처리 | 반올림(0.5 이상 올림) |
| Q3 | 쿠폰 주문 감액 | 적립 없음(0포인트) |
| Q4 | 쿠폰 사용 판별 | `PriceBreakdown.discount > 0` |
| Q5 | VIP 가산 | 적립률 3배(1% → 3%) |
| Q6 | 회원 표현 | `{ grade: "VIP" \| "NORMAL" }`를 따로 받음 |
| Q7 | VIP + 쿠폰 | VIP는 쿠폰을 써도 3% 그대로 |
| Q8 | 범위 | 요청자가 위임 → **계산 순수 함수만**(비목표 참고). 저장·사용·회수는 별도 태스크 |
| Q9 | 상한·하한 | 요청자가 위임 → **없음**. subtotal 0원 → 0포인트 |

- [x] `src/pricing/points.ts`가 `(PriceBreakdown, { grade })`를 받아 0 이상 정수 포인트를 반환하는 순수 함수다
