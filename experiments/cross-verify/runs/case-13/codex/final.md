판정: rejected

### 근거

- 배송비 정책 지정·규칙 10 · 입력: 상품 `[{"sku":"A","name":"A","unitPrice":10000,"quantity":1}]`, 쿠폰 `[]`, 정책 `{"fee":1000,"freeThreshold":20000}` · 기대: 배송비 1,000원, 결제 11,000원 · 실제: 전달한 정책이 무시되어 배송비 3,000원, 결제 13,000원.
- 규칙 1: 정률 계산 후 원 미만 버림 · 입력: 상품 `[{"sku":"A","name":"A","unitPrice":100000000000001,"quantity":1}]`, 쿠폰 `[{"scope":"order","type":"rate","value":99}]` · 기대: 할인 99,000,000,000,000원 · 실제: 부동소수점 오차로 할인 99,000,000,000,001원. 입력 금액은 안전한 정수 범위 안임.

### 확인한 것

- API: 요청한 이름·타입·내보내기와 기본 배송비 정책 선언을 코드로 대조.
- 규칙 1: 1%·33%·100%와 소수점 버림 확인. 큰 금액은 BigInt 계산과 실제 함수 결과를 비교하여 위반 재현.
- 규칙 2: 기준 금액을 초과하는 정액 할인과 기준 금액 0원 확인.
- 규칙 3: 정률·정액 쿠폰의 할인 상한과 상한 0원 확인.
- 규칙 4: 최소 주문 금액 미만·동일·초과 및 상품 할인 후에도 할인 전 합계를 사용하는지 확인.
- 규칙 5: 단가 101원·수량 3개에 정률·정액 쿠폰을 적용하여 줄 단위 계산 확인.
- 규칙 6·7: 여러 상품 쿠폰과 주문 쿠폰을 함께 적용하고 목록 순서를 뒤집어 기준 금액과 적용 순서 확인.
- 규칙 8: 상품별 중복·주문 중복·없는 SKU가 `CouponError`를 던지는지 확인. 최소 주문 금액 미달 쿠폰도 포함.
- 규칙 9: 잘못된 할인율·정액·상한·최소 주문 금액·누락된 SKU의 `CouponError` 확인.
- 규칙 10: 할인 합산과 할인 후 50,000원·49,999원의 기본 배송비 경계 확인. 사용자 지정 정책 위반 재현.
- 규칙 11: 빈 장바구니에서 잘못된 쿠폰을 무시하고 모든 금액 0원 반환 확인. 쿠폰 접근 시 오류를 내는 Proxy로 미접근도 확인.
- 규칙 12: 배열과 내부 객체를 동결하여 실행하고 전후 값을 비교해 입력 불변 확인.
- `pnpm check`: 타입 검사 통과. 테스트 실행은 임시 디렉터리 생성 권한 오류(`EPERM`)로 차단되어 ALL PASS는 확인하지 못함. 이는 구현 위반 판정 근거에 포함하지 않음.
