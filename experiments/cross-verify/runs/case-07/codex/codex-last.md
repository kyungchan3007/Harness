### 근거

- 규칙 5 — 상품 쿠폰은 대상 줄 금액 기준 · 입력: A 10,000원×2개, B 30,000원×1개, A에 10% 쿠폰 · 기대: 할인 2,000원 · 실제: 전체 합계 50,000원을 기준으로 할인 5,000원.
- 규칙 2·5 — 정액 할인은 대상 줄 금액 이하 · 입력: A 100원×1개, B 900원×1개, A에 500원 정액 쿠폰 · 기대: 할인 100원 · 실제: 할인 500원.
- 규칙 5·8·10 — 서로 다른 상품에 각 1장 적용하고 할인 합계를 반환 · 입력: A·B 각각 1,000원×1개, 각각 100% 상품 쿠폰 · 기대: `{subtotal:2000, discount:2000, shipping:3000, total:3000}` · 실제: 할인 4,000원으로 계산하여 `RangeError` 발생.

### 확인한 것

- API: 요청한 이름·타입·함수 인자 및 기본 배송비 정책을 코드로 확인.
- 규칙 1: 333원의 10%가 33원, 101원×3개의 10%가 30원임을 실행 확인.
- 규칙 2: 주문 정액 쿠폰의 상한은 정상. 상품 정액 쿠폰은 위 반례에서 실패.
- 규칙 3: 정률·정액 쿠폰의 `maxDiscount`와 상한 0원 적용 확인.
- 규칙 4: 최소 금액 미달 시 해당 쿠폰만 제외, 경계값 포함, 할인 전 합계 기준 확인.
- 규칙 5: 수량을 포함한 줄 단위 계산 및 여러 상품 입력 확인. 대상 줄 대신 전체 합계를 사용하는 결함 발견.
- 규칙 6: 주문 쿠폰이 상품 할인 차감 후 금액을 사용하는 구조와 실행 결과 확인. 상품 할인 오류는 주문 할인에도 전파됨.
- 규칙 7: 쿠폰 배열 순서를 뒤집어도 상품 쿠폰부터 적용되는 결과 확인.
- 규칙 8: 상품별 중복·주문 중복·없는 SKU는 `CouponError` 확인. 서로 다른 상품의 유효 쿠폰 조합에서 위 오류 재현.
- 규칙 9: 잘못된 범위·소수·`NaN`·무한대·SKU 누락의 오류와 유효 경계값 확인.
- 규칙 10: 할인 합산, 할인 후 무료배송 기준 50,000원 경계, 사용자 지정 배송 정책 확인.
- 규칙 11: 빈 장바구니에 잘못된 쿠폰을 전달해도 모든 금액 0 반환 확인.
- 규칙 12: 배열과 내부 객체를 동결한 입력으로 정상 실행 및 변경 없음 확인.
- 메모리 내 직접 검증: 44건 중 41건 통과, 3건 실패. 파일은 수정·생성하지 않음.
- `pnpm check`: 타입 검사 통과. 테스트 실행은 임시 디렉터리 생성 권한 오류(`EPERM`)로 차단되어 ALL PASS는 확인하지 못함. 환경 오류와 테스트 파일 유무는 거절 근거로 사용하지 않음.
