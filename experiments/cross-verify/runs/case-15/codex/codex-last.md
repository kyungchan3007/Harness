### 근거
- 규칙 1·10 — 정률 할인은 원 미만 버림 · 입력: `items=[{"sku":"A","name":"A","unitPrice":9007199254740991,"quantity":1}]`, `coupons=[{"scope":"order","type":"rate","value":33}]` · 기대: 할인 `2972375754064527`, 결제 `6034823500676464` · 실제: 할인 `2972375754064526`, 결제 `6034823500676465`.
- 규칙 11 — 빈 장바구니는 쿠폰을 보지 않고 모든 금액 0 반환 · 입력: `items=[]`, `coupons=[{"scope":"item","sku":"A","type":"fixed","value":1}]` · 기대: `{subtotal:0,discount:0,shipping:0,total:0}` · 실제: `CouponError: 장바구니에 없는 상품입니다: A`.

### 확인한 것
- API: 인터페이스·오류 클래스·함수 이름과 타입이 요청과 일치하며 기본 배송비 정책을 사용함.
- 규칙 1: 999원의 10%가 99원임을 확인. 안전한 정수 범위의 큰 금액에서는 BigInt 계산과 비교해 위 오차 확인.
- 규칙 2·3: 정액 할인은 기준 금액으로 제한되고, 정률·정액 모두 `maxDiscount`가 적용됨. 상한 0도 확인.
- 규칙 4: 최소 주문 금액 미달 시 해당 쿠폰만 제외됨. 경계값과 할인 전 합계를 기준으로 판단함을 확인.
- 규칙 5: 단가 333원·수량 3의 상품에 10% 적용 시 줄 금액 기준 99원 할인 확인.
- 규칙 6·7: 상품 할인 후 잔액에 주문 할인 적용. 쿠폰 배열을 역순으로 넣어도 같은 결과 확인.
- 규칙 8: 같은 상품 쿠폰 중복·주문 쿠폰 중복·없는 상품 대상에서 `CouponError` 확인.
- 규칙 9: 할인율 범위 초과·소수·음수·NaN·Infinity, 잘못된 선택 금액, sku 누락에 대한 오류 확인.
- 규칙 10: 할인 합산, 기본·사용자 지정 배송비의 무료배송 경계, 최종 결제 금액 확인.
- 규칙 11: 빈 장바구니에 잘못된 할인율·상품 쿠폰·중복 주문 쿠폰을 넣으면 오류가 발생함을 확인.
- 규칙 12: 배열과 내부 객체를 동결한 입력으로 정상 계산 확인. 코드에서도 입력 변경 없음.
- `pnpm check`: 타입 검사 통과. 테스트는 임시 디렉터리 생성 권한 오류(`EPERM`)로 실행되지 않아 ALL PASS 미확인. 환경 오류와 테스트 파일 유무는 거절 근거에 포함하지 않음.
