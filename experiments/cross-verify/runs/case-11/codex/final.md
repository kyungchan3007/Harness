판정: rejected

### 근거

- 규칙 1(정률 계산 후 원 미만 버림) · 입력: 상품 `[{"sku":"A","name":"A","unitPrice":100000000000001,"quantity":1}]`, 쿠폰 `[{"scope":"order","type":"rate","value":99}]` · 기대: 할인 `99000000000000`원, 결제 `1000000000001`원 · 실제: 할인 `99000000000001`원, 결제 `1000000000000`원. 안전한 정수 입력이지만 중간 곱셈의 정밀도 손실로 1원 과다 할인되며, 상품 쿠폰에서도 동일하게 재현됩니다.

### 확인한 것

- API: 요청한 이름·타입·함수 시그니처와 기본 배송비 정책을 코드로 대조했습니다.
- 규칙 1: 일반 소수점 버림과 큰 금액을 실행하고, `BigInt` 계산으로 위반을 확인했습니다.
- 규칙 2: 상품·주문 정액 쿠폰이 기준 금액까지만 할인하는지 확인했습니다.
- 규칙 3: 정률·정액 쿠폰의 할인 상한과 상한 0원을 확인했습니다.
- 규칙 4: 최소 주문 금액 미달 시 해당 쿠폰만 건너뛰고, 경계값에서는 할인 전 합계로 적용하는지 확인했습니다.
- 규칙 5: 단가 101원·수량 3개에 33%를 적용하여 줄 전체에서 한 번 계산하는지 확인했습니다.
- 규칙 6: 상품 할인 합계를 뺀 금액으로 주문 할인을 계산하는지 확인했습니다.
- 규칙 7: 쿠폰 목록을 뒤집어도 결과가 같은지 확인했습니다.
- 규칙 8: 상품·주문 쿠폰 중복과 없는 상품에 대해 `CouponError`를 확인했습니다.
- 규칙 9: 범위 밖 값·소수·`NaN`·무한대·누락된 sku의 오류와 유효한 경계값을 확인했습니다.
- 규칙 10: 할인 합산, 기본·사용자 지정 배송 정책의 무료 배송 경계, 결제 금액을 확인했습니다.
- 규칙 11: 빈 장바구니에 잘못된 쿠폰을 전달해도 모든 금액이 0인지 확인했습니다.
- 규칙 12: 배열과 내부 객체를 동결하여 실행하고 입력 불변을 확인했습니다.
- 일반 동작 검증 49건과 타입 검사는 통과했습니다. `pnpm check`는 테스트 실행 중 임시 디렉터리 생성 권한 오류(`EPERM`)로 실패했으며, 이는 구현 위반의 근거로 삼지 않았습니다.
