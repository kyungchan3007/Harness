# 0040 — 연구실 시료 보관 엔진 — PRD

- **이슈:** #1

## 문제·목표
- **문제:** 실제 연구실의 시료 관리는 복잡하지만, 에이전트가 이해하고 구현하기 위해서는 규칙이 명확하고 작아야 한다.
- **목표:** 시료(액체) 수신·분취·예약·소비·폐기·이동·책임자 변경을 기록하는 엔진을 만든다. 공개된 규칙(R1~R8)만 따르고, 실제 연구실 관행은 다루지 않는다.
- **비목표:** 장소/용기/책임자 그래프의 검증, 실제 시각, 동시 실행, 저장소.

## Acceptance
- [x] 시료 상태(ACTIVE/DEPLETED/DISCARDED)와 예약 상태(ACTIVE/CANCELED/CONSUMED)를 추적한다
- [x] 수신(receive)이 계보의 시작 시료를 만들고, 분취(split)가 부모-자식 계보를 만든다
- [x] 예약(reserve)과 소비(consume)가 "이용 가능량" 개념으로 사전 할당을 지원한다
- [x] 이동(move)과 책임자 변경(transferCustody)이 용기와 책임자 상태를 관리한다
- [x] R7(같은 eventId 재전송) 멱등성을 구현한다
- [x] R8 원자성: 실패 시 상태 무변화, 성공 시만 seq 증가 및 이력 기록
- [x] 규칙 R1~R8 모두: 규칙마다 단위 테스트 1개 이상
- [x] `pnpm check` ALL PASS

## 규칙 요약
- **R1 참조:** 목록에 없는 엔티티는 거부 (UNKNOWN_*)
- **R2 계보:** receive만 루트를 만들고, split이 계보 관계와 수량 보존을 유지
- **R3 예약:** 예약은 "이용 가능량"(remaining - reserved)만 줄이며, consume이 양쪽 다 소비
- **R4 상태:** ACTIVE/DEPLETED/DISCARDED, 끝난 상태는 되살릴 수 없음
- **R5 용기:** 시료는 용기에 고정, move로 용기 변경 가능
- **R6 책임자:** receive에서 지정, split은 부모 책임자 상속, transferCustody로 변경
- **R7 멱등성:** 같은 eventId·인자면 처음 Receipt 반환, 다른 인자면 EVENT_CONFLICT
- **R8 원자성:** 성공 시만 seq 증가와 이력 기록, 실패 시 무변화

## 애매한 곳·가정
- 시료 ID는 샘플과 용기, 예약이 각각 독립적이므로 같은 글자여도 됨 — (가정)
- "여러 규칙을 어기는 호출"은 어긴 규칙 중 아무 오류 코드나 반환 가능 — (가정, 규칙 8번 말미 기반)
- split 원자성: 중간에 실패하면 이미 만든 자식도 모두 롤백 — (가정)
- containerId가 이동 시점에 비어 있는지만 검사하고, 명령 중간에 다른 호출이 끼어들 수 없음 — (가정, 메모리 엔진이므로)
