# SDD — 연구실 시료 보관 엔진

- **접근:** 메모리 기반 상태 관리 엔진을 TypeScript로 구현한다. 8가지 연산(receive, split, reserve, cancel, consume, discard, move, transferCustody)의 각 호출마다 검증 → 원자성 있는 커밋을 수행하며, 실패 시 상태 변화를 허용하지 않는다. eventId 기반 중복 호출 감지(R7)로 멱등성을 보장한다.

- **대안·트레이드오프:**
  1. 검증 타이밍: 명령 시작 시점에만 상태 확인(선택) vs 다단계 검증. 이유: R5, R8에서 명령 시작 시점 기준이 명시됨.
  2. reserved 필드: 독립 필드로 유지(선택) vs 실시간 계산. 이유: O(1) 조회 성능, R3 이용 가능량 계산 효율.
  3. 계보 역참조: 부모-자식 맵 유지 vs 필요시 탐색. 이유: snapshot에서 자식 조회 요청 없음, 불필요.

- **검증 계획:**
  1. 단위 검사: 8개 연산 × 8개 규칙 × 오류 코드별 시나리오 (64개 이상).
  2. 통합 검사: R2(수량 보존), R7(중복 호출), R8(원자성) 강제.
  3. 공개 예시 검증: 요청의 5가지 시나리오 (예: split 후 move, 예약 중 consume).
