# 0040-lab — 실험실 시료 보관 엔진 PRD

- **이슈:** #1

## 목표
가상의 연구실에서 시료(액체)를 받아들이고, 나눠 담고, 예약하고, 쓰고, 버리고, 옮기는 일을 기록하는 엔진을 구현합니다.

## 범위
- 메모리 안에서 한 번에 한 호출씩 처리 (저장소, 동시 실행, 실제 시각 미포함)
- 실패는 예외가 아닌 `{ ok: false, code }` 형태
- 모든 명령은 eventId를 첫 인자로 받음
- 공개 계약은 `src/lab/types.ts` 기준

## 핵심 개념

### 대상
- **장소(location)**: 카탈로그에 있는 것만 유효
- **용기(container)**: 장소에 고정, 용량 있음, 한 번에 시료 최대 1개
- **시료(sample)**: 용기에 담긴 액체, 양은 정수 μL
- **예약(reservation)**: 시료의 일정량을 미리 잡아둠
- **책임자(custodian)**: 시료 관리 담당자
- **이벤트(event)**: 성공한 명령의 기록

### 상태
- 시료: ACTIVE, DEPLETED(0이 됨), DISCARDED(폐기됨)
- 예약: ACTIVE, CANCELED, CONSUMED

## 주요 기능

### 1. 시료 수입 (`receive`)
- 새 시료를 용기에 담아 받음
- 시료는 root(parentId=null, rootId=자신)

### 2. 시료 분취 (`split`)
- 부모 시료에서 자식 시료 1개 이상 생성
- 자식 양의 합 ≤ 부모의 이용 가능량
- 자식 containerId는 각각 달라야 하고, 비어있어야 함

### 3. 예약 (`reserve`)
- ACTIVE 시료의 이용 가능량 범위 내에서만 예약
- 예약 양은 남은 양을 줄이지 않음 (이용 가능량만 줄임)

### 4. 예약 소비 (`consume`)
- ACTIVE 예약의 **양 전체** 소비
- 남은 양과 reserved 함께 줄임
- 예약을 CONSUMED로 변경

### 5. 예약 취소 (`cancel`)
- ACTIVE 예약을 CANCELED로 변경
- 잡아둔 양 해제

### 6. 폐기 (`discard`)
- ACTIVE 예약이 없는 ACTIVE 시료의 남은 양 전부 버림
- 상태를 DISCARDED로 변경, 용기 비움

### 7. 이동 (`move`)
- 시료를 다른 용기로 이동
- 목표 용기는 비어있고 용량이 충분해야 함
- 양·예약·책임자·계보는 변하지 않음

### 8. 책임자 변경 (`transferCustody`)
- 시료의 책임자만 변경
- 부모·자식에게 번지지 않음

## 제약사항

### 계보·수량 보존 (R2)
- 시작 시료의 받은 양 = 계보 내 모든 시료의 (남은 양 + 소비량 + 폐기량)
- 분취는 소비가 아님

### 이용 가능량 (R3)
- **이용 가능량 = 남은 양 − ACTIVE 예약 양의 합**
- 예약은 이용 가능량만 줄임, 남은 양은 그대로

### 이벤트 멱등성 (R7)
- 같은 eventId + 같은 인자로 다시 호출 → 첫 Receipt 반환, 상태 변화 없음
- 같은 eventId + 다른 인자 → `EVENT_CONFLICT`
- 실패한 명령의 eventId는 기록 안 함 (다시 시도 가능)

### 원자성 (R8)
- 성공하면 이벤트 기록, seq 증가 (처음부터 1)
- 실패하면 아무것도 변하지 않음 (split의 자식 모두 성공하거나 모두 실패)
