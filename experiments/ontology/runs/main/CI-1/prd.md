# 0040 — 연구실 시료 보관 엔진 — PRD

- **이슈:** #1

## 목표

연구실에서 시료(액체)를 받아들이고, 나눠 담고, 예약하고, 소비하고, 폐기하고, 옮기는 일을 기록하는 메모리 내 엔진 구현.

## Acceptance

- [ ] `src/lab/lab.ts`에 `createLab(catalog: Catalog): Lab` 구현
- [ ] 모든 명령(receive, split, reserve, cancel, consume, discard, move, transferCustody) 구현
- [ ] R1~R8의 모든 규칙 준수 (ontology.json 참조)
- [ ] `pnpm check` 통과
- [ ] 8개 명령의 공개 예시 4가지 모두 통과

## 주요 규칙

- **R1**: 장소·용기·책임자·시료·예약은 카탈로그/기록에 있는 것만 참조 가능
- **R2**: 계보·수량 보존 — 시작 시료 = 모든 시료의 (remaining + consumedQty + discardedQty) 합
- **R3**: 예약은 사용 가능량을 줄이지만 실제 양은 소비할 때만 줄어듦
- **R4**: 상태는 ACTIVE → DEPLETED(남은 양 0) 또는 DISCARDED(폐기)
- **R5**: 분취 시 자식 용기들도 같은 명령 안에서 비어있고 서로 달라야 함
- **R6**: 분취 자식은 부모의 책임자를 이어받음, 옮기기로 책임자는 그대로
- **R7**: 성공한 같은 eventId로 같은 명령을 다시 보내면 Receipt만 돌려주고 상태 불변
- **R8**: 원자성 — 다중 자식 분취는 모두 성공하거나 모두 실패, 실패 후 상태는 명령 전 그대로

## 범위

- 메모리 내 구현만 (저장소, 동시성 X)
- 실패는 예외가 아니라 `{ ok: false, code }`
- 호출당 하나의 명령만 처리
