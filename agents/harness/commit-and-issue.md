# 커밋·이슈·PR 지침서 — 허점 · 보완 · 컨텍스트·토큰

기능을 만들고, 테스트하고, 자동화하면서 드러난 것을 **커밋·이슈·PR에 남깁니다.** 코드 변경만 보면 "무엇을 했는지"는 알지만, "무엇이 약했고 얼마나 들었는지"는 알 수 없기 때문입니다.

## 세 섹션

| 섹션 | 질문 | 쓰는 법 |
| --- | --- | --- |
| `[허점]` | 이번 작업에서 **드러난** 엔지니어링 허점은? | 하네스·테스트·설계·자동화의 빈틈, 오탐·미탐, 잘못된 가정. 없으면 `- 발견 못 함: <확인한 범위>` (그냥 "없음" 금지) |
| `[보완]` | 무엇을 **보완해야** 하나? | 후속 작업, 미해결 위험, 다음에 검증할 것. 태스크로 만들었으면 번호를 적는다 |
| `[컨텍스트·토큰]` | 이 작업에 컨텍스트·토큰을 **얼마나** 썼나? | 직접 쓰지 않는다. `pnpm usage`가 transcript에서 집계해 자동으로 채운다 |

> `#`으로 시작하는 줄은 git이 주석으로 지우므로 섹션 제목은 `[허점]` 형식을 쓴다.

## 커밋 메시지 형식

```
feat(0017): 커밋·이슈 지침서 + 토큰 자동 집계

- 변경 내용 요약

[허점]
- 커밋 전 메시지는 게이트(pnpm check)가 볼 수 없어 hook으로만 강제된다

[보완]
- CI에서도 PR 커밋 메시지 검사 (0007과 함께)

[컨텍스트·토큰]
- 범위: 브랜치 task/0017-commit-issue-guide 누적 · 세션 1개 · 요청 42회 · 모델 claude-opus-5-5
- 토큰: 입력 120 · 캐시 쓰기 85.3k · 캐시 읽기 3.12M · 출력 41.0k
- 컨텍스트: 최대 168.2k · 마지막 161.9k
- 읽은 파일: 23개

Co-Authored-By: ...
```

## 자동화

| 장치 | 언제 | 하는 일 |
| --- | --- | --- |
| `pnpm usage` | 아무 때나 | 현재 태스크 브랜치의 토큰·컨텍스트 집계 (`--commit`이면 섹션 형식) |
| `.githooks/prepare-commit-msg` | 커밋 직전 | `[컨텍스트·토큰]`이 없으면 `pnpm usage --commit` 결과를 트레일러 앞에 넣음 |
| `.githooks/commit-msg` | 커밋 직전 | 태스크 브랜치 커밋에 세 섹션이 없거나 비면 **커밋 거부** (머지·fixup·revert 제외) |
| `pnpm install` | 설치 시 | `core.hooksPath=.githooks` 자동 설정 |

## 토큰 집계 방식

- **출처:** Claude Code transcript (`~/.claude/projects/<프로젝트>/**/*.jsonl`, 서브에이전트 포함). 요청마다 `usage`·`gitBranch`가 기록된다.
- **태스크 귀속:** `gitBranch`가 현재 태스크 브랜치인 요청만 합산 → **브랜치 누적**. 마지막 커밋의 수치가 태스크 총량.
- **중복 제거:** 같은 응답이 스트리밍으로 여러 줄 기록되므로 `message.id`로 한 번만 센다 (그냥 합산하면 약 2.6배 과대).
- **컨텍스트:** 요청마다 `입력 + 캐시 읽기 + 캐시 쓰기` = 그 순간 모델이 본 컨텍스트 크기. 최대값과 마지막 값을 보고.
- **다른 폴더에서 연 세션:** 브랜치로 잡히지 않으므로 `pnpm usage --commit --transcript <파일> --since <ISO 시각>`으로 시간 구간을 집계해 직접 붙인다.
- **한계:** Claude Code에서만 집계된다(Codex 미지원). transcript 형식이 바뀌면 "집계 불가"로 표시되고 커밋은 막지 않는다.
