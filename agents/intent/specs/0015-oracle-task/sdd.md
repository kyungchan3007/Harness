# 0015 — 역할 분리 실험 과제(쿠폰) + 숨겨진 채점용 테스트 — SDD

요구사항: [prd.md](prd.md)

## 설계
- **읽은 문서:** 0012 sdd(실험 설계·채점 방식·oracle 누출 위험), 0014 sdd(준비 커밋 메시지 힌트 누출), `domain.md`·`price-cart.ts`(기존 할인·배송비 규칙), `checks.sh`
- **접근:**
  1. **과제 문장** [`experiments/role-split/task.md`](../../../../experiments/role-split/task.md) — 규칙 12개에 번호를 붙이고, 함수 모양(`priceWithCoupons`·`Coupon`·`CouponError`)을 코드로 고정한다. 경계(이상/초과, 버림, 줄 단위, 할인 전/후)는 모두 문장에 적는다.
  2. **채점용 테스트** `oracle/coupon.oracle.ts` — 21개. 이름 앞의 T번호가 함정, `(규칙 N)`이 근거 문장. 파일 이름이 `.test.`가 아니라서 원본 저장소의 `pnpm test`에는 잡히지 않고, 채점할 때만 복사본의 `src/pricing/coupon.oracle.test.ts`로 들어갔다가 빠진다.
  3. **정답 구현** `reference/coupon.ts` — 채점 기준을 검증하는 데만 쓴다.
  4. **채점 기준 자체 검증** `selfcheck.mjs` — 새 복사본에서 ① 구현 없음 → 0개 통과 ② 정답 → 전부 통과 + 타입 검사 통과(함수 모양이 과제 문장과 맞음) ③ **틀린 구현 21개**(정답 코드의 한 곳을 바꿔치기) → 노린 함정 테스트가 실패 ④ 모든 함정이 적어도 한 틀린 구현으로 확인됨. 하나라도 어긋나면 실패. 게이트에 연결.
  5. **복사본 준비** `prepare.mjs` — `git archive`로 한 시점을 꺼내 새 저장소에 커밋 하나(`initial`, 작성자 `dev`)로 만든다. 이력이 없으니 준비 과정의 커밋 메시지가 남지 않는다. `experiments/`와 실험 관련 태스크(0012~0016) 기록 폴더를 빼고, 작업 보드·일지·LEARNINGS 표에서 그 태스크 행을 지운다. 끝에 **누출 검사**(oracle·채점·정답·실험군·함수 이름·실험 경로, 커밋 1개)를 해서 걸리면 실패.
  6. **채점** `score.mjs` — 복사본에 채점 테스트를 넣고 vitest JSON 결과를 함정별 통과/실패로 바꿔 남긴 뒤 테스트를 다시 뺀다.

- **대안·트레이드오프:**
  - 함수 모양을 에이전트에게 맡기기: 설계 자유도는 실험 대상이 될 수 있지만, 채점 테스트가 호출할 수 없어 정확도를 못 잰다. → 모양만 고정하고 내부 설계는 자유.
  - 틀린 구현을 파일 21개로: 읽기는 쉽지만 정답을 고칠 때마다 21개를 따라 고쳐야 하고 어긋나도 모른다. → 정답 코드 바꿔치기 목록. 바꿔치기 대상이 사라지면 자체 검증이 실패한다.
  - 복사본을 `rsync` + 기존 이력 유지로: 빠르지만 0014처럼 커밋 메시지·이력이 힌트가 된다. → 이력 없는 새 저장소.
  - 누출 검사를 사람이 눈으로: 0014에서 놓쳤다. → 키워드 검사를 스크립트에 넣고 걸리면 실패.
  - 실험 관련 흔적을 전부 지우기(가드레일 문서의 0013·0014 설명, hooks 주석): 역할 분리 장치 자체가 그 문서·코드라 지울 수 없다. → 정답·채점 정보만 막고, "역할 분리 실험이 있다"는 사실이 보이는 건 허용(두 실험군에 똑같이 보인다).
- **파일 계획:** `experiments/role-split/{task.md, oracle/coupon.oracle.ts, reference/coupon.ts, lib.mjs, lib.test.mjs, prepare.mjs, score.mjs, selfcheck.mjs}`, `package.json`(`exp:*`), `checks.sh`
- **위험:**
  - 에이전트가 원본 저장소 경로를 찾아 채점 파일을 읽을 수 있다(복사본은 임시 폴더지만 같은 컴퓨터). → 0016에서 실행 후 자동 기록·세션 기록에서 원본 경로·채점 파일 접근을 검사한다.
  - 과제 문장에 없는 것을 테스트가 요구하면 불공정 → 테스트마다 근거 규칙 번호를 달고, 경계가 문장에 없는 조합(예: 최소 주문 금액 미달인 중복 쿠폰)은 테스트하지 않는다.
  - 자체 검증이 게이트에 들어가 약 10초가 늘어난다.
- **검증 계획:** 자체 검증(0/21 → 21/21 → 틀린 구현 21개 각각 해당 함정 실패), 커밋 후 복사본에 `experiments/`가 실제로 빠지는지 누출 검사로 확인, 복사본에서 `pnpm check` ALL PASS(시작 상태가 깨끗해야 공정), 단위 테스트, `pnpm check`

## 계획과 달라진 점
- 누출 검사를 처음 돌렸을 때 **제외하려던 0012~0016 기록 폴더가 그대로 들어가 있었다.** 경로 제외 규칙(`specs/0012-*`)이 폴더 안 파일까지는 가리키지 않았다(`specs/0012-*/**`로 수정). 눈으로 확인했다면 "제외 목록에 넣었으니 됐다"로 넘어갔을 실수를 검사가 잡았다.
- 누출 키워드에 저장소 이름(`harness-lab`)을 넣었다가 뺐다. 이름은 곳곳에 있고 그 자체로 정답 정보가 아니다. 원본 경로 접근은 실행 후 기록으로 본다.
- **커밋 후 복사본에서 누출 5건 + 게이트 실패.** 원본의 `checks.sh`(자체 검증 한 줄)와 `package.json`(`exp:*`)이 복사본에 없는 실험 폴더를 불렀다. 커밋 전에는 원본 HEAD에 실험 폴더가 없어서 드러나지 않았다. → 준비 단계에서 그 연결을 빼고, 자체 검증에 "복사본 시작 상태 게이트 통과"를 넣었다.
- 함정 21개 중 처음엔 16개만 틀린 구현으로 확인됐다 → 5개 추가하고, "모든 함정이 틀린 구현으로 확인됨"을 자체 검증 조건으로 올렸다.

## 검증 결과
- 자체 검증(`pnpm exp:selfcheck`, 게이트 연결):
  - 복사본 시작 상태 게이트: 통과
  - 구현 없음: **0/21**
  - 정답 구현: **21/21**, 복사본 타입 검사 통과(함수 모양 = 과제 문장)
  - 틀린 구현 21개: 각각 노린 함정 테스트 실패, **21개 함정 모두 확인**
- 복사본 준비(커밋 후 HEAD 기준): 누출 0건, 커밋 1개(`dev initial`), `experiments/`·0012~0016 기록 없음, 복사본 `pnpm check` ALL PASS
- 누출 검사가 실제로 잡은 실수 2건: 제외 경로 패턴 오류, 복사본의 실험 폴더 연결(게이트·pnpm 스크립트)
- 단위 테스트 7개 추가(행 지우기·함정별 집계·함정 번호·연결 빼기), 전체 PASS
- `pnpm check` ALL PASS (자체 검증으로 약 10초 증가)
- 미검증(0016): 에이전트가 원본 경로의 채점 파일에 접근하지 않는지 — 실행 기록으로 확인해야 함
