# 0036 — 다른 회사 검사자: 같은 결함 코드를 Claude와 Codex가 검사 — PRD

- **이슈:** #56
- **문제:** 0016에서 역할을 모두 Claude(Haiku)로 나누면 검사자가 결함을 9번 중 1건만 잡았다. 같은 회사 모델끼리는 같은 곳을 못 볼 수 있다. 다른 회사 모델(Codex)이 검사하면 달라지는지 모른다.
- **목표:**
  1. 착수 전 Codex와 설계 토론, 합의한 보완을 반영한다.
  2. 정상 쿠폰 구현에 결함을 하나씩 심은 코드 23개 + 결함 없는 코드 3개를 **같은 묶음으로** Claude 검사자와 Codex 검사자에게 준다.
  3. 결함별 탐지(재현율)·잘못된 반려·함께 놓친 결함·한쪽만 잡은 결함·비용·시간을 비교한다.
  4. 설계 Codex · 구현 Claude · 검증 Codex 전체 파이프라인은 다음 작업으로 넘긴다 (구현자는 설계 문서만 받는다).
- **비목표:** 전체 파이프라인 실행, ClauseLens 적용.

## 애매한 곳·가정
- 범위 — 이번엔 검사자 실험만 (확인됨: 검사자 실험부터)
- 다음 파이프라인의 구현자 입력 — 설계 문서만 (확인됨: 설계 문서만)
- 결함 코드 — 채점 기준 자기 검사용으로 이미 있는 틀린 구현 23개를 그대로 사용 (가정: 함정마다 실패가 확인돼 결함 번호가 분명함)
- 검사자 모델 — Claude Opus 5.5·Claude Haiku 4.5 / Codex gpt-6-astra (가정: 가장 강한 모델끼리 비교 + 0016 기준선인 Haiku)
- Codex 추론 강도 — high (가정: 기본값 low는 불리, 강한 쪽으로 맞춤)
- 검사자 권한 — 둘 다 쓰기 불가(Claude는 쓰기 도구 없음, Codex는 읽기 전용 샌드박스), 판정은 마지막 메시지로 (가정: 실행 환경에서 막는 게 강제)
- 누출 차단 — 실행 중 원본 저장소의 정답 구현·결함 목록·채점 테스트·결과 키를 읽기 금지(chmod 000) + 실행 기록에서 복사본 밖 경로 감사 (가정: 미리 표식 파일로 차단 확인함)
- 탐지 판정 — 검사자가 누구인지 모르는 채점 AI(Sonnet)가 "심은 결함을 규칙·조건까지 짚었나"를 판정 (가정)
- 횟수 — 코드마다 검사자별 1번 (가정: 26개 코드가 반복 역할)
