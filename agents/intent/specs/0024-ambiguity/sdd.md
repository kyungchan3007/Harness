# 0024 — 모호한 요청에 AI는 되묻는가, 지어내는가 — SDD

요구사항: [prd.md](prd.md)

## 설계
- **읽은 문서:** 0016 sdd(실패 원인 = 빈칸 지어냄, 실행 장치), 0022 sdd(원문 고정, 설계자 지시 "원문에 없음 — 설계 결정" 표시), `experiments/role-split/run.mjs`(0016 실행 지시에 "사람에게 되묻지 말고 끝까지 진행" 문장)
- **접근:**
  1. **과제** `experiments/ambiguity/task.md` — 새 기능 "포인트 적립". 쿠폰이 아닌 이유: 쿠폰은 0015에서 규칙이 이미 정해져 빈칸이 없음.
  2. **정답지** `answer-key.json` — 애매한 곳 7개(주요 5·부수 2)와 분명한 곳 3개.

| ID | 애매한 곳 | 무게 |
| --- | --- | --- |
| M1 | "결제 금액"이 배송비 포함인가 | 주요 |
| M2 | 1포인트 미만 끝수 처리 | 부수 |
| M3 | 쿠폰 주문은 "좀" 얼마나 줄이나 | 주요 |
| M4 | 쿠폰을 썼는지 무엇으로 아나 (코드베이스에 쿠폰 없음) | 주요 |
| M5 | VIP는 "더" 얼마나 | 주요 |
| M6 | VIP인지 무엇으로 아나 | 주요 |
| M7 | VIP가 쿠폰을 쓰면 | 부수 |

  3. **조건 3가지 × 3회** (Haiku 4.5, 0015 복사본 장치 재사용)
     - A: "저장소 규칙대로 처리" — 평소
     - Q: A + "모호하면 추측해서 구현하지 말고 질문으로 정리해 답을 받으라"
     - BR: 역할 분리 + 원문 고정(0022) — 설계자 지시에 "원문에 없는 것은 '원문에 없음 — 설계 결정'으로 표시"가 이미 있음
     - **세 조건 모두 0016의 "되묻지 말고 끝까지" 문장을 뺐다.**
  4. **판정** `judge.mjs` — 채점 AI(Sonnet 5.5)에 정답지 + 산출물(마지막 메시지·prd·sdd·trace·판정서·도메인 문서 변경·코드)을 주고 항목마다 asked / assumed / silent. 같은 항목에 질문과 가정이 다 있으면 asked. 분명한 곳에 대한 질문은 과잉 질문으로 따로 셈. 판정 일부는 직접 확인.
  5. **지표:** 판정 분포, **주요 항목을 몰래 지어낸 수**, 과잉 질문 수, 되묻고 구현을 멈췄는지, 시간·비용.
- **대안·트레이드오프:**
  - 대화형으로 답을 주고 이어 가기: 실제 사용에 가깝지만 자동 반복이 어렵다 → 이번엔 "첫 응답에서 무엇을 하는가"만.
  - 판정을 키워드로 기계 판정: 재현성은 좋지만 "가정 명시"를 문맥 없이 못 가린다 → 채점 AI + 직접 확인.
  - 0016 실행 지시 그대로: 비교는 쉽지만 "되묻지 말라"가 들어 있어 실험이 무의미 → 뺐다.
- **파일 계획:** `experiments/ambiguity/{task.md, answer-key.json, run.mjs, judge.mjs, judge-lib.mjs, judge-lib.test.mjs, runs/}`, `experiments/role-split/lib.mjs`(제외 목록에 0024)
- **위험:**
  - 채점 AI 판정 오류 → 직접 확인 표본, 판정 근거(인용) 저장.
  - 저장소 규칙(기록 강제·종료 돌려보냄)이 "멈추고 묻기"를 방해할 수 있음 → 그것도 결과로 기록.
- **검증 계획:** 판정 함수 단위 테스트, 시범 1회씩으로 장치 확인, 9회 실행·판정, 표본 직접 확인, `pnpm check`
