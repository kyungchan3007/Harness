# 0034 — (확인됨: 답)을 대화 기록과 대조 — PRD

- **이슈:** #50
- **문제:** 0033에서 Haiku 1번(SI-2)이 막히자 사람에게 묻지 않고 `(확인됨: …)`을 스스로 적어 통과했다. 0032 규칙은 `(확인됨: …)` 표시만 보고 답이 실제 사람 답인지 보지 않는다.
- **목표:**
  1. 0034부터 `(확인됨: 답)`의 답이 대화의 사람 메시지(첫 요청 제외)에 있어야 통과시킨다.
  2. 수정 직전 차단과 응답 종료 점검에 건다.
  3. 0033 대화 기록으로 SI-1 통과·SI-2 차단을 확인한다.
  4. Haiku 3회를 새로 돌려 위조가 막히면 무엇을 하는지 본다.
- **비목표:** "없음"으로 덮기 막기, 다른 세션에서 받은 답.

## 애매한 곳·가정
- 사람 메시지의 범위 — 직접 친 글만, 첫 요청은 제외 (가정: 첫 요청에 있는 값이면 애매한 곳이 아니고, 요청을 인용한 확인은 위조와 같다)
- 답이 "있다"의 기준 — 답의 숫자는 모두 있어야, 숫자가 없으면 두 글자 이상 낱말의 절반 이상 (가정: 문장을 바꿔 적어도 핵심 값은 남는다)
- 어디에 거는가 — 수정 직전 hook·응답 종료 hook만, 게이트는 제외 (가정: 게이트는 대화 기록을 못 본다)
- 새 실행 조건 — 0033과 같음(Haiku, 지시 없이, 문답 최대 3번, 흔한 의도), 작업 번호만 0034 (가정)
