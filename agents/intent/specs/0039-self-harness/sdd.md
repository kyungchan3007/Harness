## 설계

## 근거 (외부)
- Self-Harness(arXiv 2606.09498): 실행 기록에서 모델별 실패 패턴 → 규칙 변경 제안 → 평가 게이트 통과 시 반영
- AHE(arXiv 2604.25850): 모델 고정, 에이전트가 프롬프트·도구·미들웨어·메모리 수정 → 이득은 주로 도구·미들웨어·메모리
- 주의: 하네스 개선 능력은 모델 크기와 비례하지 않음, 자기 예측 퇴행은 대부분 실현 안 됨 → 예측 말고 실측 게이트

### 결론
- **원문 위치를 안 알려 줘도 Haiku는 정책 문서를 스스로 찾는다** — 5회 모두 docs 5개를 문서마다 3~7번 읽음, 학습 규칙 5회 모두 100
  - 0038 후속 질문("위치 안내가 없으면?")의 답: 이 과제 크기·문서 배치에선 위치 안내가 하는 일이 없음 (0038 결론 강화)
  - 단, 문서 5개가 `docs/`에 모여 있는 작은 저장소 — 문서가 흩어진 큰 저장소에선 다를 수 있음
- **Self-Harness는 "반복되는 실패"가 있어야 돌아간다** — 정책 실패가 없으니 개선할 신호가 없었음
- **실제로 반복된 실패는 규칙이 아니라 작업 습관** — 게이트 로그를 작업 폴더 밖에 쓰기 5회 중 3회(점수와 무관한 임시 파일)
  - 이것이 다음 Self-Harness 무대 후보: 실패 신호가 자연히 반복되고, 고칠 대상이 하네스 문구(작업 폴더 규칙)라 텍스트 개선과 맞음

- 소요 시간이 채점 시각 기준 → 완료 알림 duration_ms
