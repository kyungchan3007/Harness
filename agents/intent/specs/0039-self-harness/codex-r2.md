**3) 제안자 저장소 탐색 금지**

- **[참고] 장점:** 입력을 통제하고 정책 복사·평가 장치 열람을 막습니다. 신고만으로 유용한 지침을 만들 수 있는지 분명하게 측정합니다.
- **[중대] 단점:** 실행 기록도 숨기므로 탐색 실패인지 구현 실패인지 구별하기 어렵습니다. 결과가 정책 재진술이나 일반적인 “문서를 확인하라”에 머물 수 있습니다.
- **[중대] 취지 판정:** SDD가 정의한 실패→제안→게이트 구조에는 맞지만, **실행 기록 기반 Self-Harness의 제한된 변형**입니다. Sonnet이 Haiku를 개선하는 실험이므로 “Haiku의 자기 개선 능력”으로 부르면 안 됩니다. 공개 정책 열람 자체를 정보 누출로 부르는 설명도 과도합니다.

**4) 게이트·최종 조건별 6회의 해석**

**[중대] 게이트는 잠정 채택 규칙이지 통계적 성공 판정이 아닙니다.** 다음을 사전 고정해야 합니다.

- 점수 집계: 규칙별 평균인지, 기존 채점기의 규칙군별 평균인지. 평가군은 R10이 2개여서 결과가 달라집니다.
- 회귀 45개 전부 통과의 적용 범위와 명시 규칙 −5%p의 비교 단위.
- 미실행·계약 변경·시간 초과·인프라 오류의 처리 및 예비 3회 사용 기준.

최종 표본은 **조건별 실행 6개**입니다. 테스트 수나 규칙 수로 표본을 늘려 세면 안 됩니다. 실행별 결과와 묶음별 차이·불확실성을 보고하고, 후보 미채택 시 H-auto가 H0와 같은 처치임을 명시해야 합니다.

| 말해도 되는 문장 | 안 되는 문장 |
|---|---|
| “이 과제·모델·동결 후보에서 평가 5개 규칙의 평균 점수가 H0보다 X%p 높게 관측됐다.” | “미관측 정책이나 새 과제에 일반화했다.” |
| “직접 신고하지 않은 규칙에서 개선이 관측됐으며 정책 중첩이 있다.” | “독립적인 평가 정책으로 전이했다.” |
| “개발 게이트의 사전 기준을 통과했다.” | “통계적으로 개선과 무회귀가 보장됐다.” |
| “후보는 채택되지 않았다.” | “자동 하네스 개선은 효과가 없다.” |
| “위치 안내·정책 강조 기준선과 비교했다.” | “자동 개선이 사람보다 우수하다.” |
