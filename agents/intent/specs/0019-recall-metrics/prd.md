# 0019 — 복기 참조·체크박스 측정 도구 + 기준선 — PRD

- **문제:** 사용자가 겪는 두 문제를 **감으로만** 알고 있다.
  1. 다음 날 작업할 때 에이전트가 전날 복기(아쉬운 점·보완할 점·이전 커밋)를 보지 않는다.
  2. 이슈 체크박스가 작업 완료 후에도 제대로 채워지지 않는다.
  개선 장치(0020)를 넣기 전에 **현재 수준을 수치로** 재야, 장치가 효과가 있었는지 판단할 수 있다.
- **목표:** 대화 기록(transcript)·커밋·GitHub 이슈를 읽어 아래 지표를 뽑는 `pnpm metrics`를 만들고, ClauseLens 실제 기록으로 **기준선**을 잰다.
- **비목표:** 개선 장치(0020), 반복 허점의 자동 분류(사람이 판단), 대화 내용(프롬프트 원문)을 결과에 남기기(public repo).

## 지표

| 영역 | 지표 | 정의 |
| --- | --- | --- |
| 복기 | 참조율 | "새 작업의 시작"(하루 첫 요청 또는 새 브랜치 첫 요청)마다, **첫 코드 수정 전**에 과거 기록을 읽은 비율 |
| 복기 | 참조 종류 | 작업 기록(JOURNAL·LEARNINGS·TASKS) · 태스크 문서(prd·sdd·trace) · 메모리 · git·이슈 이력 · Notion |
| 복기 | 반영률 | 커밋 `[보완]` 항목 중 이후 커밋·TASKS에서 다시 언급된 비율 (후보 자동 추출, 사람 확인) |
| 체크박스 | 방치율 | 닫힌 이슈의 미체크 항목 중 **사유 없는** 것의 비율 |
| 체크박스 | 수동 지시 | 사용자가 "체크해줘" 류로 직접 지시한 횟수 |
