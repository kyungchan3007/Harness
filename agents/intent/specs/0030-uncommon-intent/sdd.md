- 추측이 맞힌 4점은 모두 T2(반올림) — `Math.round`를 고른 역할 분리 4번

**직접 확인**
- 숨겨진 테스트 자체 검증(oracle-check): 기준 구현 5/5, 한 곳씩 틀린 구현 6개가 노린 테스트에서만 떨어짐.
- Opus 대화형 3회 첫 메시지에서 M1 질문("결제 금액에 배송비도 들어가나요?")을 직접 찾음 — 스스로 물음. 답으로 "할인 전 상품 합계"를 받아 구현.
- Haiku 대화형 3회는 M1을 묻지 않음 → 3회 모두 `total`(할인 후 + 배송비)로 계산. T1 실패, T5(VIP+쿠폰)는 M7 답을 받았는데도 기준 금액이 틀려 실패.
- 혼자 정함 재채점은 0027에서 만든 연결 파일을 그대로 써서 AI 비용 없음.

**관찰**
1. **추측의 점수는 "의도가 흔한가"에 달려 있었다.** 같은 구현인데 흔한 의도 41% → 흔하지 않은 의도 4%. 0026에서 Sonnet 역할 분리가 80%였던 것도 대부분 흔한 선택을 골라 맞힌 것이었다(0%로 떨어짐).
2. **묻고 답을 받으면 의도와 상관없이 맞는다 — 단 빠짐없이 물었을 때만.** Opus 대화형은 두 의도 모두 100%. Haiku 대화형은 87% → 60%: 묻지 않은 M1이 흔한 의도에선 "운 좋게" 맞았지만 흔하지 않은 의도에선 틀렸다. 빈칸 하나가 다른 답(M7)까지 무너뜨린다.
3. **묻는 것의 진짜 가치 = 추측 대비 +96%p** (Opus 대화형 100% vs 추측 평균 4%). 흔한 의도에선 +59%p로 작아 보였던 이유는 추측이 흔한 선택에서 공짜 점수를 얻었기 때문.

**결론 (각 3회 — 경향)**
- 0027·0028의 결론("묻고 답을 받으면 맞는다")은 **쉬운 의도 덕이 아니었다** — 흔하지 않은 의도에서도 Opus 대화형 100%.
- 반대로 "AI가 알아서 잘 정한다"는 착시였다: 요청자의 의도가 흔한 선택과 다르면 추측은 거의 0점이다. 실제 요청자의 의도가 흔한지 아닌지는 미리 알 수 없다.
- 그래서 애매한 요청은 **추측하게 두지 말고, 빠짐없이 묻게 하고 답한다.** 묻는 쪽은 큰 모델이 확실하다(Haiku는 M1을 3번 다 놓침).
