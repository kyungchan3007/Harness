# 0012 — 역할 분리 실험 설계 — SDD

요구사항: [prd.md](prd.md)

## 설계
- **읽은 문서:** 0009 sdd(guard·records.mjs 구조), guardrails.md, Notion AI Harness 02. 역할 분리 · 06. 강제·게이트(Evidence Gate: 구현자 ≠ 판정자), 0008 sdd(hooks 입력 필드), hooks 문서 확인 결과(`agent_type` 필드)
- **접근:**
  1. **역할 = Claude Code 서브에이전트.** `.claude/agents/{designer,builder,verifier}.md`로 정의하고, 각 역할이 쓸 수 있는 도구도 제한한다(검증자는 Edit 없이 `verdict.md` Write만).
  2. **역할 식별:** hook 입력의 `agent_type`(서브에이전트 이름)으로 "지금 누가 수정하는가"를 안다. 역할이 없는 메인 세션은 **조율자**로 보고 기존 0009 규칙만 적용한다.
  3. **역할별 권한 강제:** `records.mjs`에 역할 → 허용 경로 표(`ROLE_PATHS`)를 두고 `guard.mjs`가 `decideEdit`에 역할을 넘긴다. 권한 밖 수정은 exit 2로 차단하고 "이 파일은 ○○ 역할의 일"이라고 안내한다.
  4. **판정 흐름:** 검증자는 `verdict.md`에 `approved` 또는 `rejected`와 근거(어느 Acceptance·규칙을 어떤 입력에서 어겼는지)를 쓴다. rejected면 구현자에게 돌아가고, **최대 2회** 반려 후에도 실패하면 `blocked`.
  5. **게이트:** 역할 분리 모드 태스크(prd에 `역할 분리: on`)는 `verdict.md`가 `approved`여야 PASS.

```
설계자 ──prd·sdd──▶ 구현자 ──src·테스트──▶ 검증자 ──verdict──┐
                       ▲                                      │
                       └──────── rejected (최대 2회) ◀─────────┘
                                 approved ──▶ 게이트 ──▶ 완료
```

- **비교 실험 설계:**

| 항목 | 내용 |
| --- | --- |
| 과제 | **쿠폰 규칙** — 정률 할인(원 미만 절사)·할인 상한·최소 주문금액(할인 전 기준)·상품쿠폰 → 주문쿠폰 적용 순서·무료배송 기준(할인 후) 연동. 경계값이 얽혀 틀리기 쉬움 |
| 실험군 A | **1인 에이전트** — 현재 강제 장치(0009)만, 설계·구현·자기검증 모두 혼자 |
| 실험군 B | **역할 분리** — 설계자 → 구현자 → 검증자, 역할별 권한 강제 |
| 공통 조건 | 같은 요구사항 문장, 같은 모델, 같은 시작 커밋, 원격 없는 복사본 |
| 채점 | **숨겨진 채점용 테스트(oracle)** — 함정별 테스트 약 20개. 실행 중인 복사본에는 없고, 끝난 뒤에만 넣어 돌린다 |
| 반복 | 실험군마다 **3회** (에이전트 결과의 편차) |

| 지표 | 측정 방법 |
| --- | --- |
| 🎯 정확도 | oracle 테스트 통과 수 / 전체 |
| 🔍 검증자가 잡은 결함 | `verdict.md`의 rejected 근거 중 실제 결함인 것 |
| 🙈 놓친 결함 | oracle은 실패했는데 자기 검증·검증자가 통과시킨 것 |
| 💸 비용 | 소요 시간, 도구 호출 수(`trace.auto.jsonl`), 반려 왕복 횟수 |
| 🧱 경계 위반 시도 | 역할 밖 수정 시도(`blocked` 기록) 횟수 |

- **대안·트레이드오프:**
  - 역할을 세션 여러 개(사람이 순서대로 실행)로: 식별은 쉽지만 자동 반복 실험이 어렵다. → 서브에이전트 + `claude -p --agent`로 자동화.
  - 역할을 프롬프트로만 부여: 권한 경계를 넘어도 막을 수 없어 "분리"가 아니게 된다. → hooks로 강제(0009 교훈: 문서 규칙은 건너뛴다).
  - 검증자에게 수정 권한도 주기: 빠르지만 검증자가 구현자가 되어 "구현자 ≠ 판정자"가 무너진다. → 판정만.
  - 채점을 에이전트가 쓴 테스트로: 자기가 쓴 테스트는 자기 착각을 공유한다. → 숨겨진 oracle.
  - 1회씩만 비교: 에이전트 결과 편차가 커서 우연과 구분 불가. → 3회. 비용이 크면 줄이되 그 사실을 결과에 명시.
- **파일 계획 (구현 태스크에서):** `.claude/agents/*.md`, `hooks/lib/records.mjs`(`ROLE_PATHS`, 역할 판정), `hooks/guard.mjs`, `evals/check-task-records.mjs`(verdict 검사), 템플릿 `verdict.md`, `experiments/role-split/`(과제 문장·oracle·실행 스크립트·결과)
- **위험:**
  - **`agent_type`이 PreToolUse 입력에 실제로 오는지 미확인** — 문서 확인 결과로는 서브에이전트일 때 온다고 되어 있으나 e2e로 본 적 없다. 안 오면 역할 식별 설계 전체가 바뀐다. → **0013 첫 단계에서 e2e로 먼저 확인**하고, 안 되면 대안(역할별 git 브랜치·환경 변수)으로 전환.
  - Bash로 쓰는 파일은 역할 경계도 사전 차단 못 함(0009 한계와 동일). 검증자 도구에서 쓰기 가능한 Bash 제외로 완화.
  - 자동 실험 실행이 권한 분류기에 막힐 수 있음(0009에서 권한 우회 실행 거부됨) → 허용 도구를 좁힌 실행으로 시도, 막히면 사용자가 직접 실행.
  - oracle 누출: 에이전트가 oracle을 보면 채점이 무의미 → 실행 복사본에서 `experiments/role-split/oracle/`을 제거하고 시작.
- **검증 계획:** (이 설계 태스크) 권한 표·흐름·실험 설계가 prd Acceptance를 모두 덮는지 대조, TASKS 분해가 의존 순서대로인지 확인, `pnpm check`
