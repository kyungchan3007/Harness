# 0012 — 역할 분리 실험 설계 — PRD

- **문제:** 지금은 에이전트 하나가 설계·구현·검증을 모두 한다. 자기가 만든 코드를 자기가 검증하면 같은 착각을 반복해서, 스스로 놓친 결함을 스스로 잡기 어렵다. ClauseLens도 "구현자 ≠ 판정자"(Evidence Gate)를 규칙으로 두었지만, 그 효과를 측정해 본 적은 없다.
- **가설:** 단계별로 역할을 나누면(설계자 → 구현자 → 검증자) 1인 에이전트보다 **숨은 결함을 더 많이 잡는다.** 대신 비용(시간·도구 호출·왕복)이 늘어난다.
- **목표:**
  - 역할별 수정 권한을 **hooks로 강제**하는 장치를 설계한다(문서 규칙이 아니라 장치로 — 0009와 같은 원칙).
  - 1인 에이전트와 역할 분리를 **같은 과제·같은 채점 기준**으로 비교하는 실험을 설계한다.
  - 구현 태스크를 쪼개 TASKS에 등록한다.
- **비목표:** 이번 태스크에서 구현·실행하지 않는다(설계만). 모델별 분리(Claude ↔ Codex)와 모듈 소유권 분리는 후속 실험.

## 역할 정의

| 역할 | 하는 일 | 수정할 수 있는 것 | 수정할 수 없는 것 |
| --- | --- | --- | --- |
| 🎯 설계자 (designer) | 요구사항을 규칙·Acceptance로 고정 | `prd.md` · `sdd.md` · `domain.md` · TASKS | `src/` |
| 🔨 구현자 (builder) | sdd대로 코드·테스트 작성 | `src/` · `trace.md` | `prd.md` · `sdd.md` (**스펙을 코드에 맞춰 고치지 못하게**) |
| 🔍 검증자 (verifier) | 스펙 대비 코드 판정 | `verdict.md` · `trace.md` | `src/` · 스펙 (**직접 고치지 않고 판정만**) |
