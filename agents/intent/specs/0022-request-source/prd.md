# 0022 — 원문 고정 강제 — PRD

- **이슈:** #24
- **문제:** 0016에서 역할 분리(B)가 21점 중 4·5점. 조율자가 설계자에게 원래 요청 대신 요약을 넘겨 설계자가 규칙을 지어냈고, 검사자는 그 문서를 기준으로 통과시켰다. 원문을 모든 역할이 읽게 하자(B′) 3회 만점이었지만, 그건 **프롬프트 지시**라 조율자가 안 지키면 다시 무너진다.
- **목표:** 원문 전달을 장치로 강제한다.
  1. **원문 파일** — 태스크 폴더 `request.md` = 이슈 본문 그대로. `pnpm request <이슈>`로 만든다.
  2. **원문 고정** — 이미 있는 `request.md`는 누구도 수정 불가. 새로 만들기는 역할 없는 메인만(역할 에이전트가 원문을 쓰면 요약이 원문 행세를 함).
  3. **읽기 전 수정 차단** — 역할 에이전트는 **그 실행에서** `request.md`를 읽기 전에는 어떤 파일도 고칠 수 없다.
  4. **판정 근거** — 원문이 있는 작업의 판정서는 회차마다 `### 원문 대조`(원문 규칙별 확인) 필수.
  5. **완료 검사** — 역할 분리 작업은 `request.md` 필수.
- **비목표:** 원문을 "이해했는지" 판정(읽음은 도구 기록일 뿐 — 점수로 확인), 조율자 직접 수정 차단(0013 한계, 별도).
