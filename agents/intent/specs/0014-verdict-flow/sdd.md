# 0014 — 검사자 판정 흐름 — SDD

요구사항: [prd.md](prd.md)

## 설계
- **읽은 문서:** 0012 sdd(판정 흐름: rejected면 구현자에게, 최대 2회 후 blocked), 0013 역할 권한(검사자는 verdict.md만), `records.mjs` `inspectTask`, `.claude/agents/verifier.md`
- **접근:**
  1. **판정서 형식** (`verdict.md`, 회차를 아래로 쌓는다 — 지우지 않는다):
     ```
     ## 1차 · 2026-09-30
     판정: rejected
     ### 근거
     - 배송비 규칙 2 — 입력: 할인 후 50,000원 / 기대: 배송비 0원 / 실제: 3,000원
     ### 확인한 것
     - pnpm check 실행 (통과) · 경계값 49,999 / 50,000 직접 계산
     ```
     - 반려(rejected)는 `### 근거`에 항목 1개 이상, 각 항목에 "기대"와 "실제"가 있어야 유효.
     - 통과(approved)는 `### 확인한 것`에 항목 1개 이상이 있어야 유효(근거 없는 느슨한 통과 방지).
  2. **판정 로직** `hooks/lib/verdict.mjs`: `parseVerdict(text)` → 회차 목록, `verdictStatus(rounds)` → `{ next: "verifier" | "builder" | "done" | "blocked", rejections, problems }`. 반려 3회 이상이면 blocked.
  3. **`pnpm verdict [NNNN]`** — 현재 작업(또는 번호)의 판정서 상태와 다음 차례를 출력.
  4. **완료 검사** — `inspectTask`: 판정서가 있으면 형식을 검사하고, prd에 `- **역할 분리:** on`이 있는 작업이 TASKS에서 done이면 `next === "done"`이어야 통과.
  5. **검사자 지시** — `.claude/agents/verifier.md`에 형식·회차 쌓기·근거 규칙을 넣고, 템플릿 `templates/verdict.md` 추가.
- **대안·트레이드오프:**
  - 회차마다 파일을 새로 (verdict-1.md …): 파일이 늘고 최신 찾기가 번거로움. → 한 파일에 회차를 쌓는다(이력 보존).
  - 반려 근거를 자유 서술: 구현자가 무엇을 고칠지 모호해지고 검사도 불가. → "기대/실제" 필수.
  - 통과에는 근거 없이: 느슨한 통과를 못 막음. → "확인한 것" 필수.
  - 반려 한도 없음: 끝없는 반복·비용. 한도 1회: 한 번의 실수로 바로 사람 개입. → 0012 설계대로 2회.
  - 검사자가 실제로 테스트를 돌렸는지 강제: 판정서만으로는 불가. → 자동 기록의 `role: verifier` 도구 호출(Bash `pnpm check` 등)로 사후 확인(0016 지표).
- **파일 계획:** `hooks/lib/verdict.mjs`(+test), `evals/verdict.mjs`(명령), `hooks/lib/records.mjs`(완료 검사 연결), `.claude/agents/verifier.md`, `templates/verdict.md`, `package.json`, guardrails.md
- **위험:** 형식 검사가 너무 엄격하면 검사자 AI가 형식 때문에 막힘(0012 오탐 교훈) → 형식을 짧게, 템플릿 제공, e2e로 실제 AI가 쓰는 형식 확인.
- **검증 계획:** 파서·상태·완료 검사 단위 테스트, 복사본에서 버그+틀린 테스트를 심은 작업으로 검사자→구현자→검사자 실제 실행, `pnpm check`

## 계획과 달라진 점
- e2e 준비에서 정책 주입 테스트도 같은 경계값을 확인하고 있어 함께 "버그에 맞게" 바꿨다(테스트가 모두 통과하는 상태를 만들기 위해).
- **실험 설계 허점:** 준비 커밋 메시지("테스트도 버그에 맞춤")가 복사본 기록에 남아, 검사자가 판정 근거에 그 메시지를 참조했다. 경계값을 직접 계산하기도 했지만, **힌트 없이 잡았을지는 이번 실행으로 단정할 수 없다.** → 0015·0016 실험에서는 준비 과정을 중립적인 커밋 하나로 합치고 버그·정답을 드러내는 흔적을 남기지 않는다.
