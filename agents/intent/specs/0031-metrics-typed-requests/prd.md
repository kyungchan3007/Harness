# 0031 — 측정 도구: "체크 수동 지시"는 직접 친 요청만, [보완] 반영률은 기간 적용 — PRD

- **이슈:** #43
- **문제:** 2026-10-09 ClauseLens 재측정에서 0019 측정 도구의 "사용자의 체크 수동 지시"가 크게 부풀려져 있었다(10/1~10/2 "8회" → 직접 입력 0회, 이식 전 "9회" → 3회). 그 숫자로 10/2에 "체크해줘 2일 5회, 오히려 증가"라는 틀린 결론을 냈다. `[보완]` 반영률은 기간 옵션을 무시했다.
- **목표:**
  1. 요청 이벤트에서 사람이 직접 친 부분만 남긴다(셸 명령·출력, 시스템 안내, 붙여 넣은 글, 명령 태그 제거, 대화 요약 제외, `uuid` 중복 제거).
  2. "체크 수동 지시"를 요청형 문장으로 좁힌다.
  3. `[보완]` 반영률이 `--since`·`--until`을 따르게 한다.
  4. ClauseLens로 다시 재서 손으로 확인한 값과 맞는지 본다.
- **비목표:** 복기 참조율 판정 규칙 변경, ClauseLens `REASON_MARK` 오판.

## 애매한 곳·가정
- 요청형의 범위 — "체크해줘/채워줘/체크 안 해/왜 확인 안 해" 같은 지시·불만만 (가정: 체크박스를 언급만 한 문장은 지시가 아님)
- 시간대 없는 시각 — UTC로 봄 (가정: transcript timestamp가 UTC이고 기존 복기 쪽 문자열 비교와 같게)
- 기간 적용 범위 — `[보완]`을 남긴 커밋에만, "이후 언급"은 그 뒤 전체에서 찾음 (가정: 기간 끝에서 잘라 버리면 최근 항목이 늘 0%가 됨)
