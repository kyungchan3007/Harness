# 0023 — 채점표 세 번째 입력값 테스트 + 지난 실행 재채점 — SDD

요구사항: [prd.md](prd.md)

## 설계
- **읽은 문서:** 과제 문장 `experiments/role-split/task.md`("`shippingPolicy`를 주지 않으면 기본 배송비 정책"), 0016 B′-3 판정서(1차 반려 근거), 채점 테스트·자체 검증 코드, `runs/*/coupon.ts.txt`
- **접근:**
  1. **T22** — 기본 정책과 결과가 **달라지는** 값으로 정책을 넘긴다: 상품 60,000원 + 주문 쿠폰 5,000원, 정책 `{ fee: 5,000, freeThreshold: 100,000 }` → 할인 후 55,000원은 기본 정책이면 무료배송이지만 이 정책이면 배송비 5,000원, 결제 60,000원. 근거는 "함수 모양" 문단과 규칙 10.
  2. **틀린 답안 2개** — ① 정책 인자를 무시하고 항상 기본 정책 ② 세 번째 입력을 옵션 객체(`{ shippingPolicy }`)로 받음(B′-3 1차 구현과 같은 모양). 둘 다 T22에서 떨어져야 한다.
  3. **타입만 다른 위반** — `Won`은 `number`의 별칭이라 `maxDiscount?: number`로 바꿔도 실행 결과·타입 검사가 같다. 정답 코드를 그렇게 바꿔 채점·타입 검사를 돌려 "잡을 수 없음"을 확인하고, 이런 위반은 검사자(사람·AI)의 몫으로 기록.
  4. **재채점** `experiments/role-split/rescore.mjs` — 새 복사본 하나에 각 실행의 최종 코드(`runs/<id>/coupon.ts.txt`)를 넣고 채점, `runs/rescore-0023.json`에 저장. 원래 `result.json`은 건드리지 않는다.
- **대안·트레이드오프:**
  - 채점표를 새 파일로 분리(v2): 원래 21개와 섞이지 않지만 자체 검증·실행 스크립트가 둘로 갈린다. → 한 파일에 T22를 추가하고, 이전 결과는 "21개 기준"으로 명시.
  - 12번을 다시 실행: 가장 깔끔하지만 비용(약 $10)과 모델 편차가 섞인다. → 최종 코드만 재채점(코드가 같으므로 공정).
  - 타입 위반을 잡는 테스트(`expectTypeOf` 등): `Won`이 별칭이라 구조적으로 같아 구분 불가. → 기록만.
- **파일 계획:** `experiments/role-split/{oracle/coupon.oracle.ts, selfcheck.mjs, rescore.mjs, runs/rescore-0023.json}`, `lib.mjs`(제외 목록에 0023), 0015 sdd 함정 표 참조 갱신은 하지 않고 이 sdd에 기록
- **위험:**
  - T22가 과제 문장에 없는 것을 요구하면 불공정 → 값은 기본 동작과 겹치지 않게 고르고, 근거 문장을 테스트 이름에 표시.
  - 재채점 시 최종 코드가 복사본의 다른 파일(실행마다 만든 보조 파일)에 의존하면 못 돌 수 있음 → 실패하면 원인 기록.
- **검증 계획:** 자체 검증(정답 22/22, 틀린 답안 23개 각각 해당 함정 실패, 전 함정 확인), 타입만 다른 위반 확인, 재채점 12건, `pnpm check`

## 계획과 달라진 점
없음 — 재채점은 12건 모두 실행 당시 코드 그대로 돌았다(보조 파일 의존 없음).

**채점표 자체 검증** (`pnpm exp:selfcheck`, 게이트 연결)
- 구현 없음 0/22 · 정답 22/22 · 복사본 타입 검사 통과
- 새 틀린 답안 2개(정책 무시, 옵션 객체) 모두 T22에서 떨어짐 → 틀린 답안 23개, **함정 22/22 확인**

**실행 테스트로 못 잡는 위반** — 정답 코드의 `maxDiscount?: Won`·`minOrder?: Won`을 `number`로 바꿔도 채점 22/22, 타입 검사 통과. `Won`이 `number`의 별칭이라 구조가 같다 → 이런 위반은 검사자(사람·AI)의 원문 대조로만 잡힌다.
