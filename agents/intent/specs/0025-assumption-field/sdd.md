# 0025 — "애매한 곳·가정" 칸을 장치로 강제하면 가정이 남는가 — SDD

요구사항: [prd.md](prd.md)

## 설계
- **읽은 문서:** 0024 sdd(결과·한계: BR 설계자 지시를 3번 중 1번만 따름), `agents/harness/hooks/lib/records.mjs`(checkPrd·inspectTask — Stop 돌려보냄·게이트가 같은 함수를 씀), `experiments/ambiguity/run.mjs`, `experiments/role-split/lib.mjs`(복사본 제외·누출 검사)
- **접근:**
  1. **장치** `checkAssumptions(prd)` — `checkPrd`에서 0025 이후 태스크에만 호출.
     - 칸이 없음 / 비었음(템플릿 안내 줄 `(…)`만 있음) / 줄에 `가정`·`확인 필요` 표시 없음 / `없음` 줄과 다른 줄이 섞임 → 문제
     - `checkPrd`는 수정 전 검사(PreToolUse)·종료 전 검사(Stop)·게이트가 모두 쓰므로 한 곳만 고치면 세 곳에 걸린다
  2. **템플릿** prd.md에 칸과 안내 줄 추가.
  3. **실험** 0024 `run.mjs`에 AM·BM 추가 — 지시 문장은 A·BR과 **똑같고**, 복사본 저장소에만 장치가 있다. 실험 과제 번호 0030 → 장치 적용 대상.
  4. **판정** 0024 `judge.mjs` 그대로(채점 AI Sonnet 5.5, 근거 인용 필수).
  5. **지표:** 몰래 지어냄 수, 가정 밝힘 수, 칸에 적힌 줄 수와 그중 정답지 항목과 맞는 수, 시간·비용.
- **대안·트레이드오프:**
  - 설계자 지시 문장을 더 세게: 0024가 이미 "지시는 3번 중 1번"을 보여 줌 → 이번엔 장치만 바꾼다(변수 하나).
  - sdd에 칸: prd가 요구를 고정하는 문서라 prd. 역할 분리에서 설계자가 둘 다 쓰니 차이는 작다.
  - "확인 필요"가 있으면 완료를 막기: 사람 없는 실행에선 영원히 못 끝남 → 이번엔 표시만 강제.
- **파일 계획:** `agents/harness/hooks/lib/records.{mjs,test.mjs}`, `agents/intent/templates/prd.md`, `experiments/ambiguity/run.mjs`, `experiments/role-split/lib.mjs`(0025 제외·README 행 거르기·누출 단어), `README.md`(로드맵 행에 번호)
- **위험:**
  - 칸은 채우지만 엉뚱한 것만 적음(형식만 맞춤) → 판정이 항목별이라 드러남. 칸 줄 수와 정답지 일치 수를 따로 셈.
