## 검증 결과

**조건별 숨겨진 테스트 점수** (T1~T5 × 3회 = 15점. 0024·0026·0027 결과는 같은 테스트로 0027에서 채점한 값)

| 조건 | 모델 | 점수 (15점) | M1 배송비 제외 맞춤 | 평균 질문 수 | 평균 시간 · 비용 |
| --- | --- | --- | --- | --- | --- |
| 혼자 정함 (0024) | Haiku | 4 (27%) | 0/3 | - | 2.0분 · $0.22 |
| 혼자 정함 (0026) | Sonnet | 8 (53%) | 0/3 | - | 1.9분 · $0.89 |
| 대화형 (0027) | Haiku | 13 (87%) | 1/3 | 5.0 | 4.6분 · $0.45 |
| **대화형** | **Sonnet** | **15 (100%)** | **3/3** | 6.7 | 2.8분 · $1.41 |
| **대화형** | **Opus** | **15 (100%)** | **3/3** | 8.0 | 3.2분 · $0.98 |

- 비용 = 개발 AI + 요청자 분류 AI(Sonnet $0.10, Opus $0.02, Haiku $0.045)
- 6회 모두 문답 1번 만에 구현까지 감, 게이트 통과

**직접 확인**
- 6회 첫 메시지에서 M1 질문을 직접 찾음 — 모두 "결제 금액 = domain.md의 total = 배송비 포함인가, subtotal − discount인가"를 스스로 물음(요청자 답 새어 나감 없음).
- 분류 결과: 6회 모두 M1~M7 전부 물음. Haiku QI는 3회 중 M1을 1번, M4를 0번 물었음.
- 연결 파일: Sonnet·Opus 구현은 답으로 받은 입력 모양(PriceBreakdown + 회원 등급)을 그대로 따라 연결 파일이 값을 넘기기만 함.

**관찰**
1. **큰 모델 + 대화형 = 100%.** 질문 목록이 빠짐없으니(M1~M7 전부) 답도 빠짐없이 들어가 숨겨진 테스트 15/15.
2. **차이는 "무엇을 묻느냐"에서 난다.** 같은 대화형인데 Haiku는 평균 5개 질문에 M1·M4를 자주 빠뜨렸고, Sonnet·Opus는 7~8개로 모두 물었다. 0027의 "물은 만큼만 좋아진다"가 그대로 확인됨.
3. **답 없는 큰 모델은 53%에 머문다.** 드러내기만 하고 흔한 해석(배송비 포함)으로 가면 틀린다 → 드러내기(0026) + 답하기(0027)가 둘 다 있어야 맞는다.
4. **Opus가 Sonnet보다 싸다**($0.98 vs $1.41) — 질문은 더 많지만 구현이 짧았다. Opus가 질문을 가장 많이 함(평균 8개, 과잉 질문은 채점 안 함).
5. **실행 안정성:** Sonnet은 이번에도 4번 중 1번 모델 쪽 거절로 끊김(0026: 6번 중 3번). Opus는 0번.

**결론 (각 3회 — 경향)**
- 모호한 요청 묶음(0024~0028)의 답: **질문을 빠짐없이 뽑는 모델 + 답해 주는 사람 = 의도대로 만든다.** Haiku 혼자 27% → Haiku 대화형 87% → 큰 모델 대화형 100%.
- 사람이 답할 수 있는 작업이라면 큰 모델로 "질문 먼저"가 가장 확실하다. 비용은 혼자 정하는 Haiku의 약 4.5~6배지만, 다시 만드는 비용이 없다.

**한계**
- 각 3회, 과제 1개. 정답 의도가 흔한 선택과 겹쳐(0027 한계) 100%가 "쉬운 의도" 덕일 수 있음 → 흔하지 않은 의도로 재실험이 다음 후보.
- 연결 파일이 함수 모양 차이를 흡수 — 이번엔 큰 모델이 입력 모양을 물어 그대로 따랐으므로 영향 작음.
- CLI 버전이 다름(Sonnet 2.1.251, Opus 2.1.289).
