## 왜 / 무엇
- 지금까지 harness-lab은 **intent(request·prd·sdd)만으로** AI를 몰았다. 온톨로지는 일부러 넣지 않았다
- intent만으로도 실제로 동작은 했다. 그런데 온톨로지를 더하면 결과가 더 좋아지는지는 아직 재 본 적이 없다
- 이 태스크: 개념이 많은 **새 과제**로 세 조건을 같은 방식으로 돌려 비교한다
  - **A · intent만** — 원문(request)과 prd·sdd만. 지금 있는 `agents/context/domain.md`도 뺀다
  - **B · 문서형 온톨로지** — A + 개념·관계·불변식·용어를 담은 사람이 읽는 문서 (ClauseLens domain-map·glossary 형태)
  - **C · 기계 판독형 온톨로지** — A + YAML/JSON 개념·관계·제약 정의 + 어긋나면 막는 자동 검사(hook)
- 과제: 개념·관계가 많아 용어가 섞이기 쉬운 도메인 (예: 주문·반품·환불·적립 상태 전이)
- 지표: 숨겨진 테스트 정답률 · 몰래 지어냄·질문 수 · 비용·시간
- 진행: 설계는 Codex와 토론(2라운드)부터 → 구현 Claude → 검증 Codex
- 비목표: ClauseLens 적용, 온톨로지 자동 생성

## 예상 허점 · 확인할 것
- 과제가 쉬우면 A도 100%가 나와 차이가 안 보일 수 있다 → 개념 혼동이 실제로 일어나는 과제인지 시범 실행으로 먼저 확인
- B·C는 문서 분량이 늘어 비용이 오를 수 있다 → 효과 대비 비용을 같이 본다
- 온톨로지 문서 자체가 정답 힌트가 되면 안 된다 → 온톨로지는 원문에 있는 개념만 구조화하고, 숨겨진 테스트 값은 넣지 않는다
- C의 자동 검사가 지시처럼 무시되는지, 실제로 막는지 자동 기록으로 확인
