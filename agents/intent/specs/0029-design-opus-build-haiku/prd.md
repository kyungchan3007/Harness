# 0029 — 설계 Opus + 구현 Haiku 조합 — PRD

- **이슈:** #38
- **문제:** Haiku는 정해진 요구로는 97~100%(0016·0022)지만 애매한 요구는 못 묻는다(대화형 87%, 0027). 큰 모델은 빠짐없이 묻는다(대화형 100%, 0028). 정하기는 Opus, 만들기는 Haiku로 나누면 "전부 Opus"만큼 정확하고 더 싼가?
- **목표:**
  1. 대화형 실행에 조합 모드: Opus가 묻고 답을 받아 **문서까지만**, Haiku가 **새 대화**에서 그 문서를 직접 읽고 구현.
  2. 실행마다 단계별 비용·요청 수·토큰 기록.
  3. MIX 3회 실행·채점, 0028 Opus 대화형·0027 Haiku 대화형과 비교.
- **비목표:** 검사자 모델 비교, 흔하지 않은 정답 의도.

## 애매한 곳·가정
- 넘기는 방법 — 문서 파일만, 대화 요약 없음 (가정: 0016 "요약하면 요구가 사라진다"를 피하는 실제 권장 방식)
- 구현 지시 문장 — "태스크 폴더 문서를 읽고 그대로 구현" 한 줄만, "모호하면 물어보라"는 넣지 않음 (가정: 문서가 다 정했으면 물을 게 없어야 함. 지어내는지 보려고)
- CLI — 설계(Opus)는 앱 내장 2.1.289, 구현(Haiku)은 설치된 2.1.251 (가정: 0027 Haiku와 같은 조건)
- 비교 기준 — 0027·0028 결과 재사용 (가정: 같은 과제·저장소 상태 6af14ac·같은 요청자 방식)
